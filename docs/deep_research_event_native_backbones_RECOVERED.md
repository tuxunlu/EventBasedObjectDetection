## Executive summary

The workflow surveyed the 2024–2025 event-native backbone literature across 8 angles, deep-read 15 top sources, adversarially verified 10 design-critical claims (**7 survived**), and produced two concrete architectures:

- **Brief A — `EventStreamSegS7` (SSM core).** A *true* event-by-event **selective diagonal SSM** (S7-style: input-dependent, stably-reparameterized S5 complex-diagonal SSM with a parallel associative scan) run natively over the time-ordered `(x,y,t,p)` stream — replacing the baseline's per-voxel-cell scan. Distinctive moves: **dual-order scans** (native time order + a **Hilbert/z-order** spatial scan so 2D locality re-enters a 1D sequence), STREAM-style Δ-discretization from coordinate differences, Event-SSM event-pooling downsampling, and the repo's proven **dense global-context bottleneck + presence gate** kept as the FP suppressor.
- **Brief B — `EventGraphSSMSeg` (graph core).** A pure-torch spatiotemporal **graph U-Net whose message-passing *update* is a state-space recurrence** (`GSSConv`): fixed `searchsorted` grid-hash graph (O(N), export-safe, no torch-geometric), max-relative messages for spatial structure, and a diagonal S5/S7 scan along per-cell causal chains with STREAM Δ-discretization on edges. This deliberately **fuses the two families to occupy the literature's named open gap** — no published SSM does dense per-event *segmentation*, and event-GNNs do only classification/detection/flow.

**The load-bearing findings:** true event-by-event SSMs (Event-SSM, S7, STREAM) exist and are competitive on classification (97.7–100% DVS-Gesture) at tiny parameter counts (STREAM ≈ 0.2M SSM core / ≈ 1.2M total); the two most directly reusable mechanisms — **STREAM's coordinate-difference Δ-discretization** and **Event-SSM's event-pooling** — both survived adversarial verification. The **central novelty premise** — that no published SSM or graph performs dense *per-event* semantic segmentation — holds only in its **narrowed, per-event-only form**: the blanket wording was *refuted* (see Part II), but the per-event (event-only, one-logit-per-event) gap is defensible and is exactly what both briefs target.

**Three of the ten claims were refuted** (see Part II). The headline one — "no SSM does per-event segmentation" (claim #5) — was refuted because **MambaSeg is itself an SSM that does dense semantic segmentation**; the correction is to scope the gap to **per-event** (event-only, one-logit-per-event), distinguishing it from MambaSeg's dense **per-pixel, RGB+event-fused** segmentation. The other two (STREAM's parameter budget, #3; SMamba's STCA noise-dropping, #8) were judged **accurate in the literal numbers but over-generalized** to this per-event hand-seg use case. All three corrections are already folded into the briefs' novelty framing, which scope the gap to "dense *per-event*."

### Brief A — SSM backbone

#### Backbone (one-line thesis)

A TRUE event-by-event selective diagonal state-space model (S7-style: input-dependent/selective, stably-reparameterized S5 complex-diagonal SSM with a parallel associative scan) run natively over the time-ordered (x,y,t,p) event stream — NOT the current per-voxel-cell scan. This is the core; small helpers (Hilbert-order auxiliary scan, a coarse dense-context conv bottleneck, plane-fit motion features) surround it but the SSM does the sequence modeling.

#### Recommended architecture

EventStreamSegS7 — a dual-order per-event S7 SSM segmenter that replaces the baseline's per-cell voxel SSM (model/event_ssm_seg_stream.py) with a real async event-by-event scan and emits one logit per event, row-aligned to batch.labels.

PIPELINE (per SparseEventBatch, per sample b via segment-restricted scan so batch_idx boundaries never leak):
1. Per-event input tokenization. For each event build u_k = MLP([signed polarity, t_norm, centroid-RELATIVE (dx,dy) (LOSO-safe, reuse _geom_feats), Fourier features of (dx,dy,t_norm), and the repo's existing SAE normal-flow motion channels + density channels (reuse _motion_feats/_density_feats, computed under no_grad)]). d_model=128.
2. Two ordered scans, both selective (S7/S6 input-dependent A,B,Δ):
   (a) TIME scan — events in native time order (already sorted). Δt-aware discretization à la STREAM: Δ_k = (t_k − t_{k-1})·softplus(δ(u_k)), h_k = exp(A_k Δ_k) h_{k-1} + B_k u_k. Causal → also usable for streaming inference.
   (b) HILBERT scan — events reordered by a space-filling Hilbert (or z-order) index over quantized (x,y) blocked within coarse time-bins, so spatially-adjacent events become sequence-adjacent (SMamba IPL-Scan analog). Bidirectional (window processed whole; 36ms is offline). This is how 2D spatial locality re-enters a 1D scan.
   Each scan is a stack of 4 residual S7 blocks with Event-SSM event-pooling downsampling (~4× along the event axis between stages, then scatter/upsample back to per-event resolution via a retained index map). State dim N=64.
3. Dense global-context bottleneck (KEEP — the repo's measured #1 FP suppressor). Pool the fused per-event hidden states into a coarse (B, d, Hd, Wd) map (Hd=H/8), run the existing _DenseContext (3×3 + dilated convs + masked global-avg-pool = PSPNet/ASPP recipe), producing whole-frame context the pure 1D scans cannot see. MambaSeg dual-branch-interaction analog, but single-branch (events only).
4. Per-event head. Gather back to original event order and concat: [time-scan state_k, Hilbert-scan state_k, bilinearly-sampled dense context at (x,y), per-event dynamic-energy (SSM state temporal variance = DMD static-veto proxy), raw features] → MLP → 1 logit/event. num_classes=1 → (N,), row i aligned to batch.coords[i]/labels[i].
5. Presence gate + DMD veto + aux occupancy: keep exactly as baseline (presence logit from masked global-avg of context log-sigmoid-gates every event logit; static-energy veto; train-only coarse occupancy head). These are ported unchanged because prior measurements showed they, not local motion, suppress the trajectory-wake FPs.

Why this should beat 0.79: the baseline collapses events into per-cell voxel snapshots BEFORE the SSM (quantizing time-within-cell and forcing all co-cell events to share one temporal sequence). A true per-event scan gives every event its own evolving state with STREAM's exact Δt spacing and S7 content-selectivity, removing that quantization while the dual Hilbert+time orders restore the spatial context a single scan loses; the dense-context/presence machinery that already earned the FP robustness is retained.

#### Novelty angle vs. prior work

First TRUE event-by-event (async, associative-scan) SSM performing DENSE per-event semantic SEGMENTATION — the explicitly identified open gap. Prior event-native SSMs (Event-SSM, S7, STREAM) do only classification/regression; prior Mamba-segmentation (SMamba, MambaSeg, PRE-Mamba) abandons per-event async by tokenizing voxels/windows — which is exactly what this repo's current 0.79 model does. The design keeps the async per-event scan (S7 selectivity + STREAM Δt discretization) yet recovers 2D spatial structure via a dual time+Hilbert scan and a dense global-context/presence bottleneck, cross-checked by a scan-consistency loss. It converts the repo's Tier-3 voxel SSM into a Tier-1 true event SSM without losing the global-context FP suppression that empirically drives the score.

#### Hyperparameters

d_model=128; S7 state dim N=64; 4 selective blocks per scan (time + Hilbert = 2 scans); event-pooling ~4× per stage (2 stages) then scatter-back; dense context Hd=Wd=H/8 (down_factor=8, or 4 if memory allows), context_channels=128, context_depth=2 dilated convs (dilations 2,4); Fourier PE bands=8 on relative (dx,dy,t); motion_features=True (radius 3), density_features=True (radius 2); head_hidden=128, dropout=0.2. Losses (TRAINING.event_loss_config): gjs_weight=1.0 (baseline's winning noise-robust term, bce_weight=0), tversky_weight=0.5 with tversky_alpha=0.7>tversky_beta=0.3 (FP suppression), lovasz_weight=0.3 (set-level F1 surrogate), presence_gate_weight=0.3, aux_shape_weight=0.2, scan_consistency_weight=0.1. Label cleanup train-only: boundary_ignore_px=2, time_ignore_frac=0.15. Optimizer AdamW lr=3e-4 cosine, SSM A/Δ params on a smaller lr (1e-3→use S7 stable reparam, no weight decay on SSM state params). num_sanity_val_steps=0. Threshold swept on val (event_eval_config), report val_event_f1_best. Target ~1.5–2.5M params.

#### Complexity & latency

O(N) per scan in event count N (~10k–100k/window); two scans + a coarse (H/8×W/8) dense conv (fixed, tiny). Hilbert/z-order reindex is one O(N log N) GPU sort per sample per window (cheap vs the scans). Parallel associative scan makes training near-linear wall-time; event-pooling 4× cuts the deep-stack cost. Expected step time comparable to the current per-cell SSM baseline (the per-cell baseline already scans B·Hd·Wd cells × T; a per-event scan of N events is similar order for typical windows) at ~1.5–2.5M params. Inference is event-rate-proportional and streaming-capable if only the causal TIME scan is used (Hilbert/bidirectional scan is offline-window-only; drop it for a strictly-causal streaming variant at some accuracy cost). Reference points: STREAM ~1.2M params / 100% DVS-Gesture; SMamba 24–26ms/frame at 16M params (our model is far smaller).

#### Pitfalls

- DDP symmetric logging: every rank must log the identical metric-key set with sync_dist=True even on all-empty/all-ignore windows, or the epoch-end all-reduce deadlocks. Keep num_sanity_val_steps=0 and one-video-per-rank previews (as the repo already does). N==0 must early-return an empty (0,) tensor.
- Row alignment across reorderings: the Hilbert scan and the event-pooling downsampling both permute/shrink the event axis; you MUST carry an index map and scatter states back to ORIGINAL event order before the head, else logits misalign with batch.labels. Add this to tools/smoke_test_event_sparse.py's row-alignment check first.
- Selective SSM stability: input-dependent Δ with STREAM's Δt=(t_k−t_{k-1})·softplus(δ) can explode without S7's stable reparameterization — use it; keep SSM params real-valued (cfloat state intermediate only) to stay DDP-safe.
- Streaming vs offline: the bidirectional Hilbert scan is NON-causal — it needs the whole 36ms window. Fine for this repo (windows processed whole) but document it; a true real-time stream must fall back to the causal time-scan only.
- Segment leakage: the associative scan must be reset/segment-restricted at batch_idx boundaries so one sample's state never bleeds into the next in the concatenated flat batch.
- LOSO ceiling honesty: the ~0.79 is near a 3-subject diversity ceiling; architecture alone may not break it. Keep centroid-relative coords (no absolute-position leak), cross-subject aug, and fix eval/threshold selection on the held-out subject — model+threshold selection leaks per the repo's own measurements.
- GroupNorm/LayerNorm only (no BatchNorm running stats — they leak the held-out subject).
- Do not drop the dense-context/presence machinery when 'simplifying' to a pure scan: prior measurements show local motion features are non-discriminative and global context/presence is the actual FP suppressor.
- Hilbert index compute on GPU: precompute a lookup or use a cheap Morton/z-order bit-interleave if a full Hilbert kernel is slow; verify it doesn't dominate step time.

### Brief B — Graph backbone

#### Backbone (one-line thesis)

EventGraphSSMSeg — a pure-torch spatiotemporal graph U-Net whose message-passing UPDATE is a state-space recurrence. The graph over events in (x,y,t) is the core backbone (message passing over grid-hash neighborhoods), but each causal edge carries a STREAM-style coordinate-difference discretization step and each same-cell temporal chain is evolved by a stable diagonal Event-SSM/S5 scan with S7 input-dependent selectivity. This closes the evidence's explicitly named open gap (no SSM does dense per-event SEGMENTATION; event-GNNs do only classification/flow) by fusing the two. Reuses the repo's proven pure-torch graph plumbing (searchsorted grid graph, index_select gather, presence gate, LOSO-safe centroid-relative coords) so weights transfer to a micro-window streaming runtime and export to ONNX/TensorRT.

#### Recommended architecture

Input: SparseEventBatch (coords x,y; feats [pol,t_norm]; times[0,1]; labels; batch_idx; dense_mask). Node features = centroid-relative (dx,dy) scaled by frame diagonal (LOSO-safe) + t + optional polarity. 4-level graph U-Net. (1) GRAPH CONSTRUCTION: fixed voxel-offset grid-hash graph via searchsorted (NOT kNN/FPS, NOT torch_geometric) — O(N), deterministic, export-safe. Base grid at stride 4 over 480x640, T=6 time-bins with time axis PRESERVED at every pool (stride=(1,2,2); collapsing time is the documented failure). Two edge sets: (a) spatial-neighbor causal edges Δt<=0 over a 3x3 spatial x [-1,0] temporal offset stencil (max degree K<=18, hard-capped so edges = N*K never explode); (b) a per-cell temporal-predecessor chain giving each spatial cell a well-defined sequential axis for the SSM scan. Coordinate normalization: (dx,dy) in ~[-1,1], t in [0,1]; edge Δt drives the SSM step Δ_k = Δt·softplus(δ) (STREAM). (2) OPERATOR = GSSConv (Graph State-Space Conv), 2 per level (8 total) + 3 decoder refine convs: per node it (i) computes a max-relative message max_j MLP([h_j-h_i, edge_geom]) for local spatial structure, and (ii) advances a diagonal SSM state along the causal same-cell chain h_k = exp(A·Δ_k)h_{k-1} + B·Δ_k·u_k with a stably-reparameterized diagonal A (Event-SSM/S5) via a parallel associative scan, gated by an S7 input-dependent selectivity σ(MLP(node)) controlling B and retain. Fine levels stay strictly causal (exact train-dense/run-async transfer); coarse levels run a BIDIRECTIONAL scan (MambaPupil LTV biGRU analog) for full-window context. (3) NODE+GLOBAL CONTEXT: hierarchical coarsening = Event-SSM event-pooling as graph pooling (grid /2 spatial only). Global-state token = masked-mean coarse descriptor broadcast to every event, made DUAL-TEMPORAL-SCALE (PRE-Mamba): one token from fine-time pooling + one from a coarse-time pooling, concatenated, so both fast finger motion and slow arm sweep are summarized. (4) PER-EVENT HEAD (the open gap / MambaSeg dense-decoder analog, but per-event): U-Net decoder upsamples coarse->fine (skip-add + GSSConv refine), gather decoded fine-node ctx back to each event by the pooling inverse-index, concat [node ctx, raw feats, re-injected per-event geometry (keeps sub-voxel boundary precision), dual-scale global token] -> MLP(head_hidden=128) -> ONE logit per event, row-aligned to batch.labels. (5) PRESENCE GATE (validated null-state fix, carried unchanged): per-window 'hand present?' logit from the global descriptor; its log-sigmoid is added (suppress-only) to every event logit, active at train AND inference; supervised by an aux BCE. Cut static-window FPs 2.16%->0.76% in-repo. Add SMamba STCA-style spatio-temporal-isolation scoring as a SOFT per-event down-weight feature (not a hard drop — in-repo BA denoise hard-drop killed the hand). (6) LOSSES via existing EventDistillationLoss: gjs_weight (noise-robust pointwise, the repo-measured winner) + lovasz_weight (IoU set surrogate) + focal-tversky with tversky_alpha>tversky_beta (favor precision, fight the FP-dominated regime) + presence-gate BCE aux + optional coarse-occupancy aux; train-only boundary_ignore_px=2 and time_ignore_frac=0.15 label cleanup; per-epoch DDP-aggregated threshold sweep in on_validation_epoch_end for val_event_f1_best.

#### Novelty angle vs. prior work

SSM-on-a-graph for per-event SEGMENTATION. The evidence is emphatic that (a) true event-by-event SSMs (Event-SSM, S7, STREAM) exist only for classification/regression, and (b) NO published SSM does dense per-event semantic segmentation — that is a stated open gap. Every event-GNN in turn does classification/detection/flow. The contribution unifies both: the backbone is a graph (message passing over a causal grid-hash event graph — the mandate), but its message-passing UPDATE is a state-space recurrence — STREAM's coordinate-difference discretization Δ_k=Δt·softplus(δ) placed on the graph edges, an Event-SSM stable diagonal S5 scan run along per-cell causal chains, and S7 input-dependent selectivity as the edge gate — coarsened by Event-SSM event-pooling, globally reasoned by a MambaPupil bidirectional coarse level and a PRE-Mamba dual-temporal-scale token, and read out by a row-aligned per-event head with a presence gate. This is the first graph-structured state-space model, and the first (S)SM-flavored model of any kind, to do dense per-event mask distillation.

#### Complexity & latency

Compute O(N·K) for spatial message passing (K<=18 fixed) plus O(N) for the associative SSM scan along temporal chains — linear in event count, the whole point of the SSM evidence (Event-SSM/STREAM/S7 are all O(N)). N ~ 10k-100k events/window at 480x640 / ~36ms (~1.35M ev/s). Memory: the (M,K,C) edge-gather tensor dominates activations; mitigated by (i) hard degree cap K<=18, (ii) index_select gather (repo profiler: advanced-indexing backward was ~83% of bwd time; index_select's index_add backward is 1-2 orders faster), (iii) gradient checkpointing the conv edge-gather (repo-measured ~7.9GB / ~1.0s per B=8 step at base_stride=4 vs OOM without). Training throughput ~1s/step at B=8 on a 24GB GPU. Inference: train synchronously on the full window; deploy as micro-window streaming (1-5ms slices given a persistent SSM state) with the causal fine levels — an HONEST target, since no method has a measured ~1ms dense per-event seg result and pure per-event async cannot keep up at this event rate. Param budget ~0.8-1.2M (STREAM core is ~1.2M; comparable to the repo's 535k GNN and 975k SSM-stream models).

#### Pitfalls

- DDP symmetric logging: every rank must log the IDENTICAL metric-key set even for all-empty/all-ignore windows or the epoch-end sync_dist all-reduce deadlocks. Keep num_sanity_val_steps=0 and do one validation preview PER RANK (not rank-0-only) — both are already-encoded repo fixes.
- Variable graph size: N and edge count vary per batch, so the (M,K,C) edge tensor is dynamic; gradient checkpointing is mandatory to avoid OOM at fine base_stride, and degree MUST be hard-capped (K<=18). Multi-GPU also needs NCCL_P2P_DISABLE=1 or it hangs at the first collective (repo requirement).
- AVOID torch_geometric / torch_cluster: kNN/radius graphs from those libs break DDP determinism, ONNX/TensorRT export, and add a fragile CUDA-extension dependency. Stay pure-torch (searchsorted grid graph + index_select gather) as the repo already does.
- SSM numerical stability: without a stably-reparameterized diagonal A (real part clamped negative, softplus δ) the exp(A·Δ) scan explodes over long per-cell chains — S7's key fix; do not skip it.
- Never downsample the time axis. Time-collapsing pooling is the documented failure mode; keep stride=(1,2,2) and constant time_bins.
- LOSO ceiling (~0.64-0.79 F1, 3 subjects): model + decision-threshold selection LEAKS on the held-out subject, so small run-to-run deltas are within noise. Fix the eval protocol first; genuine levers are relative coords (already in), cross-subject augmentation, EMA/SWA; the real fix is a 4th subject — no architecture beats data diversity here.
- Async transfer is only exact if the FINE levels stay strictly causal; if you make fine levels bidirectional for a training-accuracy bump you forfeit the micro-window streaming deployment story.
- Soft, never hard, noise handling: an in-repo hard denoise prefilter (BA) removed the hand too. Keep SMamba STCA as a soft down-weight feature.
- model_init_args filter: defaulted new args are fine to omit in old configs, but filter_init_args needs explicit subclass __init__ signatures or kwargs get silently dropped (repo-measured gotcha).

### 1. Schöne, Sushma, Zhuge, Mayr, Subramoney, Kappel — "Scalable Event-by-event Processing of Neuromorphic Sensory Signals With Deep State-Space Models" (arXiv:2404.18508, v3 Oct 2024). Referred to as "Event-SSM." NOTE: it is an event-by-event CLASSIFICATION paper (one label per stream), NOT dense per-event segmentation — but its event-native SSM machinery is the closest published blueprint for a scalable per-event stream model.
<https://arxiv.org/abs/2404.18508>

**Architecture:** Deep stack of S5 (Simplified State-Space) layers — purely recurrent, no CNN, no graph, no attention. Configuration: 6 S5 layers; per-layer state dimension H = 64 or 128; diagonal complex state matrix Λ = -exp(Φ) + iΘ (constrained to the left half-plane for stability), with B ∈ ℂ^{H×N}, C ∈ ℂ^{N×H}, D real. Between blocks: multiplicative GeLU/sigmoid gating z_k = y_k ⊙ sigmoid(W·GeLU(y_k)), skip connections, normalization. Model sizes are tiny: 0.4M params (SHD), 0.6M (SSC), 0.8M backbone + 4.2M embedding table (DVS128). The whole model is a 1-D sequence model over the raw, time-ordered event stream (length M up to ~1.5M events per sample).

**Graph / SSM specifics:** SSM specifics. State matrix is DIAGONAL complex (S5-style), giving O(H) per-step cost vs O(H^2) for dense A. The core novelty is an ASYNCHRONOUS discretization: events are Dirac deltas u(t)=Σ δ(t−t_m)u_m; recurrence x_k = exp(Λ·δ·Δ_k)·x_{k−1} + B̄·u_k, where Δ_k is the real inter-event time gap and δ is a LEARNABLE scalar (per diagonal element) that decouples input normalization from timing. Discrete transition Λ̄_k = exp(Λ·δ·Δ_k) makes the state decay depend on the actual elapsed time between consecutive events (variable dt), so the model is genuinely asynchronous rather than fixed-rate. Ablation shows this "Dirac" integration (84.6%) beats standard ZOH discretization (74.4%) by ~10 pts, and removing timestamp info drops to 80.8% — the variable-dt gating is load-bearing. Training uses a parallel associative scan: (a_k,b_k)⊗(a_l,b_l)=(a_k a_l, a_k b_l + b_k), resolving the length-M recurrence in O(log M) depth; the same recurrence runs step-by-step at inference for streaming.

**Head & context injection:** Input embedding: each event is mapped to one of J discrete channels j_m = flatten(x,y,polarity) and looked up in a learned table u_m = E·onehot(j_m), E ∈ ℝ^{J×N}. For DVS128 that is 128×128×2 = 32768 channels — a pure spatial-index embedding (no separate x/y/pol features, no positional encoding of coordinates; all spatial structure must be learned in the embedding table, which is why it dominates param count at 4.2M). Context aggregation is temporal only, via the recurrent SSM state carried across the whole stream, plus an EVENT-POOLING operator that subsamples the sequence by factor p after each layer (M → M/p) so deeper layers see a coarser, longer-range temporal summary while the recurrent state still integrates every event. Output head: because the task is classification, the final sequence is mean/temporally pooled to a single vector → linear classifier. There is NO per-event/dense output head and NO explicit spatial (global-context) injection beyond what the shared embedding + recurrent mixing provide.

**Complexity & latency:** Linear in event count with O(log M) parallel-scan depth for training; O(H) work per event per layer (diagonal state). Streaming inference is a constant-work-per-event recurrence (true event-by-event). Scale demonstrated: ~600M events/epoch (SSC) and ~390M events/epoch (DVS) trained in 2–10 h on a single A100; individual samples up to 1.5M events processed. No explicit ms-latency/events-per-second wall-clock number is reported, but the design target is real-time streaming. GPU memory forced training on 32,768-event slices even though evaluation ran on full-length samples.

**Accuracy & datasets:** Spiking Heidelberg Digits (SHD, audio): 95.9% (+0.8 over prior SOTA). Spiking Speech Commands (SSC, audio): 88.4% (+7.7 pts, the headline result). DVS128 Gestures (vision, event camera): 97.7% — competitive but below the best frame/CNN prior (~98.8%). All are whole-stream CLASSIFICATION benchmarks; no dense/pixel-level or per-event segmentation dataset is used.

**Pitfalls / limits:** (1) Classification only — a single label per stream; the paper never emits a per-event or dense label, so the per-event OUTPUT head and spatial-coherence problem central to segmentation are unsolved here. (2) Spatial structure is encoded ONLY through a one-hot lookup table over flattened (x,y,pol); this scales as H·(W·H·2) and is 4.2M params at 128×128 — it would explode at 240×320/480 resolution and provides no built-in spatial locality/translation structure. (3) Purely temporal recurrence: no spatial neighborhood mixing (no conv/graph/attention over the 2-D field), so cross-pixel context relies entirely on the shared embedding + state — likely insufficient for figure/ground or the static-window/global-context problems noted in this repo's memory. (4) ZOH discretization is markedly worse than the Dirac/variable-dt scheme (74.4% vs 84.6%); getting the async-dt integration right is essential. (5) Training required chunking to 32,768-event windows for memory, i.e. BPTT/state-carry across chunks is a practical constraint. (6) Still trails frame-CNNs on the vision task, i.e. event-native ≠ automatically better on 2-D spatial tasks.

**Design takeaways:** - Adopt the variable-dt async discretization, not ZOH: gate each per-event state update by exp(Λ·δ·Δ_k) with Δ_k the real inter-event gap and δ a learned per-channel scalar. The paper's ablation (84.6% vs 74.4%, and 80.8% with no timestamps) shows this timing-aware decay is the single most important ingredient — bake it directly into any per-event SSM segmenter.
- Keep the state DIAGONAL-complex (S5/LRU-style) and rely on the associative parallel scan (O(log M) depth, O(H) per event). This is what lets it train on millions of events on one A100 — the same trick makes a per-event segmentation stream tractable, unlike Mamba's long-scan kernel which this repo already measured as 9x slower per-cell.
- Do NOT copy the flatten-(x,y,pol) one-hot embedding for a segmenter: it is 4.2M params at 128^2 and has zero spatial locality. For per-event dense output, replace it with a low-dim learned (polarity, t_norm) + coordinate/geom feature embedding (as EventSparseSeg already does) or a sparse-conv/graph spatial mixer, because pure temporal recurrence gives no cross-pixel context.
- Add the missing spatial-context path the paper lacks: interleave the temporal SSM with a spatial mixer (sparse conv, kNN/radius graph, or a dense global-context bottleneck) so figure/ground and static-window FPs — exactly this repo's failure modes — get a spatial signal the SSM state alone cannot supply.
- Use event-pooling (subsample by factor p per layer) to get multi-scale long-range temporal context cheaply, but for a per-event OUTPUT you must UNPOOL/route logits back to every original event (row-aligned), which this paper never does — design the decoder to restore per-event resolution, e.g. carry skip connections at full event rate.
- Exploit true streaming inference: the identical recurrence runs step-by-step at O(H)/event, so a per-event SSM segmenter can emit a label as each event arrives (constant work, no window batching) — a real latency win over frame/voxel models, provided the spatial-context module is also made incremental.


### 2. STREAM: A Universal State-Space Model for Sparse Geometric Data (Schöne, Bhisikar, Bania, Nazeer, Mayr, Subramoney, Kappel), arXiv:2411.12603.
<https://arxiv.org/html/2411.12603>

**Architecture:** A selective state-space model (Mamba-derived) that operates directly on a stream of sparse tokens (t_i, u_i) without collapsing them into frames or voxels. Each event/point is a token; a stack of STREAM blocks (6 blocks in 2 hierarchical stages for the DVS128 event model; 12 layers for point clouds) applies a selective SSM recurrence h_k = exp(A_k Δ_k) h_{k-1} + Γ_i · Linear(u_i). The event branch uses a pixel-based input encoding (~1.0M params) feeding the STREAM core (~0.2M params). There is NO explicit graph: no kNN and no radius neighborhoods. Point clouds are handled by sorting points independently along X, Y, Z and concatenating the three orderings (2N→3N sequence length), with learned scale/shift parameters that tell the model which sort dimension it is currently reading. Local structure is captured by grouping 32-point/local sets through STREAM modules before a global backbone.

**Graph / SSM specifics:** SSM, not a graph. State dimension m=32 for vision (m=4 for audio); model dimension n=32 across benchmarks. Event model: 6 STREAM blocks, L=2 hierarchical stages, spatial/temporal subsampling factor 16 progressively shrinking sequences up to ~131,072 (train on 65,536-event subsequences, eval up to ~1.5M events). Point model: 12 STREAM layers, groups of 32 points, sort order X then Y then Z concatenated. The core idea: the SSM step size is made coordinate-aware, Δ_k = (t_k − t_{k-1}) · ψ(δ), so relative differences of coordinates (time for events, spatial coord for point clouds) are injected into the selective step size — unlike vanilla Mamba where Δ is a function of u_i only and ignores the coordinate dynamics. The continuous linear dynamics integrate over sparse timestamps giving the pairwise kernel Φ(t_k,t_i)=C_k (∏_{j=i+1}^k exp(A_j Δ_j)) B_i, i.e. an O(N) attention-like interaction with no locality constraint. Serialization order is temporal for events and coordinate-sorted for point clouds.

**— note:** n/a

**Head & context injection:** Output head is a simple average pool along the sequence dimension followed by a linear classifier — this is a whole-sequence CLASSIFICATION head, not a dense per-event/per-point segmentation head. Global context is injected purely through the SSM's recurrent state carry (the hidden state accumulates all past tokens) plus the hierarchical subsampling stages; there is no separate global token, cross-attention, or decoder. For point clouds, the multi-axis sort + learned per-axis scale/shift is how orientation/global-geometry context is fused. Notably, per-point outputs (the h_k before pooling) are row-aligned to input tokens, so the backbone can in principle emit one vector per event — but the paper only demonstrates the pooled classification path.

Training is O(N log N) via a parallel selective-scan primitive, with O(log N) depth on sufficient processors, validated to ~1M-token sequences. Uses a modified Mamba selective-scan CUDA kernel adapted to map sparse geometric coordinates to hardware. No explicit FLOPs or wall-clock latency/throughput numbers are reported; the efficiency claim rests on linear-time recurrence and tiny parameter count.

**Accuracy & datasets:** DVS128-Gestures (event): 100% test accuracy on all 11 classes (first to do so); ablation single-run 98.8±0.2% vs Mamba baseline 98.6±0.7%; beats EventMamba 99.2%, matches TENNs-PLEIADES; 0.2M core + 1.0M encoder params. **Design takeaways:** - Make the SSM step size coordinate-aware, not just feature-aware: set Δ_k = (Δt_k)·ψ(coord/motion) so relative time AND relative x,y differences modulate state decay — this is STREAM's core win over vanilla Mamba and directly gives per-event geometric selectivity your sparse segmenter needs.
- Keep true per-event outputs: STREAM only average-pools for classification, but the pre-pool hidden states h_k are already row-aligned one-per-token — attach a small per-event MLP head to h_k to emit one logit per event, giving O(N) streaming segmentation with constant per-step memory (a natural fit for your SparseEventBatch/EventSparseSeg contract).
- Don't rely on a single 1D temporal scan for spatial locality: STREAM needed multi-axis coordinate sorting to recover geometry. For dense per-event masks use multiple serializations (temporal + space-filling/Hilbert or X/Y sorts) or a light kNN/submanifold-conv local stage feeding the SSM, with learned per-order scale/shift to tell the model which pass it is on.
- Exploit linear-time streaming for async inference: the O(N) recurrence with a parallel scan for training means you can train on truncated windows (STREAM used 64k-event chunks) yet run unbounded streams — but explicitly mitigate the train/eval length distribution shift (state renormalization or random-length windows) rather than ignoring it.
- Add an explicit global/null-context gate: STREAM's only global context is the one accumulating recurrent state, which is exactly the mechanism that hallucinates on static/quiet windows in your prior GC experiments — pair the SSM with a supervised presence gate or a resettable context token so background streams can be vetoed instead of leaking into every per-event logit.
- Budget capacity deliberately: STREAM hits 100% on tiny DVS128 at 0.2M params but is capacity-limited on harder tasks; for cross-subject hand/arm segmentation (a harder, LOSO-ceilinged problem) plan for a larger state dim (m≥32) and multi-stage hierarchy, and treat sub-sampling factors (STREAM used 16) as a time-axis-preserving knob rather than collapsing the temporal dimension.


### 3. S7: Selective and Simplified State Space Layers for Sequence Modeling (Soydan, Zubić, Messikommer, Mishra, Scaramuzza; ETH/UZH Robotics & Perception Group, Oct 2024). NOTE: this is NOT a segmentation paper. S7 is a general-purpose input-dependent (selective) linear SSM layer, evaluated on sequence *classification/regression*, including raw event-stream neuromorphic classification (DVS-Gesture, SHD, SSC). It builds directly on EventSSM's async-event SSM formulation. Its relevance to per-event segmentation is the event-native selective-SSM machinery, not a dense output head.
<https://arxiv.org/abs/2410.03464>

**Architecture:** Core is a stack of diagonal, input-dependent (selective) SSM layers with a stable reparameterization. Recurrence: x_k = Λ̄_k x_{k-1} + B̄_k u_k ; y_k = C̄_k x_k + D̄_k u_k, where Λ̄ (diagonal state-transition), B̄, C̄, D̄ are ALL functions of the current input u_k, produced by learned dense projections with GeLU + sigmoid gating. This is the selectivity: every step re-computes its dynamics from content. Layers are wrapped in the standard S5/S4 block style (SSM -> nonlinearity/gating -> mixing -> residual + norm), stacked several deep. Purely recurrent formulation (no hardware-specific parallel scan kernel like Mamba's), which is what makes it simple and streaming-friendly. Discretization is asynchronous per-event: x_k = exp(Λ_k · Δt_k) x_{k-1} + B u_k, so irregular inter-event time gaps Δt_k enter the state transition directly rather than being binned into frames.

**Graph / SSM specifics:** SSM path (no graph). State transition is DIAGONAL (complex/real diagonal Λ, S5 lineage), giving O(N) per-step cost. Stable reparameterization is the key math: Λ̄_k = f(Λ_k) = I − (Λ_k² + 0.5 I)^{-1}, which pins eigenvalue magnitudes into a stable band so long-sequence (very long event streams) gradients neither explode nor vanish; the paper proves this bounds the gradient norm. Input dependence covers Λ, B, C, D (vs S5 = none, vs Mamba/S6 = B, C, dt only and A input-independent). State dimension is small and task-dependent: as low as 16 units (EigenWorms genomics used 16 units / ~12k params), typically 16-32; neuromorphic models are 0.5-0.6M params (SHD/SSC) up to 4.1M (DVS-Gesture). Number of layers is modest (a few blocks), not reported as a single fixed depth. Serialization / event ordering: events are fed in raw temporal order (time-sorted stream); there is no kNN/edge-radius graph construction. Event tokenization is a bijective spatial-polarity hash T(ε) = 2·(x·s_x + y) + p for event ε=(x,y,t,p) on a sensor of size (s_x,s_y), guaranteeing a unique token per pixel-polarity so tokens never collide (an improvement over EventSSM's scheme).

**Head & context injection:** For the tasks reported, the head is a standard sequence-classification head: take the final hidden state or mean-pool hidden states over the sequence, then a dense classifier (cross-entropy) or MSE for regression. No novel head is introduced. Global context is injected implicitly through the recurrent state itself — the selective transition lets each event attend to accumulated history — plus an "Event Pooling" operation that aggregates hidden states over a temporal window of size p to downsample and inject coarser context while cutting compute. IMPORTANT for a segmenter: S7 as published has NO per-event/dense output head — it emits one label per sequence — so a per-event segmentation head (one logit per event, row-aligned) would have to be added by reading y_k at every event step rather than pooling to a single vector.

**Complexity & latency:** Linear O(L·N) in sequence length L and state dim N (diagonal SSM), constant memory recurrent inference — well-suited to streaming per-event processing. Constant factors are higher than S5 because Λ,B,C,D are recomputed per step from input. Event Pooling reduces effective sequence length/compute. The paper gives NO concrete latency/throughput/FPS numbers and no wall-clock comparison; efficiency claims are asymptotic + parameter-count based. Param counts: SHD 0.5M, SSC 0.6M, DVS-Gesture 4.1M, EigenWorms ~12k. Trained in JAX on V100 / RTX 8000.

**Accuracy & datasets:** Neuromorphic (raw event streams, no frames): DVS-Gesture 99.2% (EventSSM 97.7%, best dense 98.8%); Spiking Heidelberg Digits SHD 96.3% (EventSSM 95.5%); Spiking Speech Commands SSC 88.2% (EventSSM 87.1%, best dense 80.7%). Long Range Arena: ListOps 63.77, Retrieval 91.80, Text 87.22 — beats Mamba on average but weaker on the visual/Image LRA task (61.14%). Dynamical systems / real-world: Pendulum MSE 2.91 (S5 3.41), FitzHugh-Nagumo L2 0.0013, Human Activity Recognition 94.09%, EigenWorms genomics 97.5% with only 16 units, Walker2D kinematics MSE 0.120. All tasks are classification/regression, none are segmentation.

**Pitfalls / limits:** (1) Selectivity causes forgetting: input-dependent gating discards tokens, which hurts when exact retention matters — S7 underperforms on LRA visual/Image tasks. For dense per-event segmentation this is a real risk (a segmenter must not forget spatially-sparse foreground events). (2) No dense/per-event head exists — it is a whole-sequence classifier; the per-event output path is unbuilt. (3) No spatial inductive bias / no explicit 2D neighborhood — events are a 1D time-ordered stream, so spatial coherence must come from the tokenization or be added. (4) The reparameterization choice is critical (ablation A.6: sigmoid-based alternatives underperform); getting stability wrong breaks long streams. (5) Higher per-step constant cost than S5; no measured latency. (6) Purely recurrent = no fast parallel-scan kernel provided, so training on very long streams may be slower than Mamba's kernels.

**Design takeaways:** - Make dynamics input-dependent AND provably stable: adopt S7's selective diagonal SSM but keep its stable reparameterization Λ̄=I−(Λ²+0.5I)^{-1} (or an equivalent bounded-eigenvalue map) so million-event streams train without exploding/vanishing gradients — selectivity without a stability guarantee is the failure mode.
- Feed events natively and asynchronously: use per-event Δt in the discretization exp(Λ·Δt_k) instead of fixed time-bins, so irregular event timing shapes the state directly — this preserves fine temporal structure the voxel/frame path throws away.
- Add the missing per-event head: read the SSM output y_k at EVERY event (one logit per event, row-aligned to labels) rather than pooling to a single vector — S7 ships only a whole-sequence classifier, so the dense output path is yours to build.
- Counter selective forgetting for sparse foreground: selectivity that boosts classification will drop rare foreground events in segmentation; add a retention safeguard (bidirectional/second reverse pass, a persistent global/presence token, or reduced gating on high-motion events) so hand events survive long streams.
- Inject spatial context deliberately: S7's 1D time-order stream has no 2D neighborhood prior. Use a collision-free bijective spatial-polarity token hash T(ε)=2(x·s_x+y)+p, and/or fuse a coarse dense/global context branch, because a pure temporal SSM cannot recover spatial coherence on its own.
- Exploit the O(L·N) constant-memory recurrence for streaming/low-power inference, and use windowed Event Pooling to inject multi-scale context and cap compute — but budget for a higher per-step constant than S5 and validate real latency, since S7 reports none.


### 4. EventMamba: "Rethinking Efficient and Effective Point-based Networks for Event Camera Classification and Regression: EventMamba" (Ren, Zhou, Zhu, Lin, Fu, Huang, Fang, Ma, Yu, Cheng). Treats an event window as a raw spatio-temporal point cloud (x,y,t,p) and processes it with a PointNet++-style hierarchy fused with Mamba (S6) state-space blocks. Targets action recognition (classification) plus camera-pose relocalization and eye-tracking (regression).
<https://arxiv.org/html/2405.06116v2>

**Architecture:** Pipeline: (1) Event-cloud preprocessing — sliding-window segmentation by temporal interval R, downsample to N=1024 or 2048 points, normalize x,y,t,p to [0,1]. (2) A 3-stage hierarchical encoder. Each stage = LocalFE (spatial) + TAG (temporal aggregation) + GlobalFE (Mamba, temporal). LocalFE: Farthest Point Sampling picks centroids, KNN (K=24) groups neighbors, per-group standardization, then a residual block ResB(x)=sigma(x + M(sigma(M(x)))) with M(x)=BN(MLP(x)). (3) Head = MLP / fully-connected with hidden dim 256 emitting ONE global vector per event-cloud (class logits or pose/gaze regression). Stage centroid schedule for N=1024: 512 -> 256 -> 128; channel schedule 32/64/128 -> 64/128/256 -> 128/256/512. Point-cloud preprocessing is ~0.065 ms vs ~0.457 ms for frame stacking.

**Graph / SSM specifics:** SSM/scan-based, not a graph net (though it uses local kNN grouping like a graph). Locality via FPS + KNN with K=24 neighbors per centroid. Mamba/S6 block: standard discrete SSM h_t = A_bar h_t-1 + B_bar x_t, y_t = C h_t, with A_bar/B_bar/Delta from zero-order-hold discretization; runs over the T' (centroid) axis in strict chronological serialization order, linear in sequence length. Reported to model "temporal correlations between 512 event groups." Not disclosed in the paper: exact d_state, expansion factor, number of Mamba layers per stage, and whether the scan is bidirectional or causal (text implies unidirectional/chronological). 3 hierarchical stages (m=3).

**Head & context injection:** Output head = MLP with a 256-dim hidden layer producing a single global label/vector — there is NO per-point/per-event dense output. Global context is injected purely hierarchically: FPS progressively contracts cardinality (1024->512->256->128) so late-stage points aggregate wider spatial-temporal receptive fields, and the Mamba block mixes information across all remaining groups along time. The Temporal Aggregation Gate (TAG) sits between LocalFE and GlobalFE: an MLP(D->1)+softmax over the K grouped neighbors yields attention weights a_tk, and SA = sum(S_tk * a_tk) collapses the K temporal samples into one per-centroid feature while preserving fine temporal detail before the SSM.

**Complexity & latency:** Mamba gives linear complexity in sequence (group) length vs quadratic attention. Very small: DVS128 Gesture model 0.29M params / 0.219 GFLOPs; regression models ~0.90M params (CPR 0.476 GFLOPs, eye-tracking 0.476 GFLOPs, HMDB51-DVS 0.953 GFLOPs). Reported inference time ~5.5 ms on the CPR task. Emphasis on edge/real-time efficiency; point-sampling preprocessing ~7x cheaper than frame stacking.

**Accuracy & datasets:** Classification: DVS128 Gesture 99.2% (1024 pts; vs 99.6% frame-based at 42x params), Daily DVS 99.1% (2048 pts), DVS Action 89.1%, HMDB51-DVS 86.4% (~52% rel. gain over TTPOINT), UCF101-DVS 97.9%, THU-EACT-50 (challenging) 59.4% at ~15% of EV-ACT resources. Regression: Camera Pose Relocalization (IJRR) 0.012 m / 0.831 deg average error (+33% from adding Mamba); eye-tracking on SEET p3=0.944, MSE=1.48 px. Ablation: removing Mamba drops HMDB51-DVS from 82.1% to 57.5%.

**Pitfalls / limits:** (1) Output is a single global label — the architecture is NOT a segmenter; no per-event/per-point head exists, so it doesn't directly answer per-event dense labeling. (2) Overfits on small datasets once explicit temporal features are captured (DVS Action, Daily DVS). (3) FPS + per-window aggregation "introduces significant latency," working against true streaming/real-time use. (4) Requires dataset-specific tuning (1024 vs 2048 points); no unified config. (5) Key SSM hyperparameters (state dim, layer count, bidirectionality) are undocumented, hurting reproducibility. (6) Eye-tracking validated only on synthetic (v2e SEET) data. (7) The whole thing is window-batched (event-cloud), not a persistent recurrent stream — no cross-window state carry.

**Design takeaways:** - Treat the event window as a raw (x,y,t,p) point cloud and lean on FPS+KNN grouping (K~24) instead of voxelizing — this preserves sub-cell temporal ordering that voxel/time-bin backbones (like the repo's EventSparseSeg) collapse; but to get PER-EVENT labels you must add a decoder/feature-propagation (PointNet++ FP or kNN upsampling) that scatters the coarse centroid features back to every original event, which EventMamba omits.
- Keep spatial locality (kNN) and temporal mixing (SSM scan) as SEPARATE operators: LocalFE handles neighborhood geometry, Mamba handles long-range chronological correlations across groups. For per-event seg, mirror this split — a submanifold/graph local stage for boundaries + a linear-time SSM over the time-ordered stream for global 'hand exists / motion continuity' context.
- The Temporal Aggregation Gate (softmax-attention pool over the K grouped neighbors) is a cheap, DDP-safe way to compress a variable neighbor set into one feature while preserving fine temporal detail — a good drop-in for aggregating events within a micro-cell before the SSM, and a natural place to inject a per-event boundary/recency weight.
- Mamba's linear-in-sequence cost + tiny footprint (0.29-0.9M params, <1 GFLOP, ~5 ms) shows an SSM segmenter can be edge/streaming-cheap — but serialization order matters: they enforce strict chronological order over centroids. For a per-event segmenter, pick the scan order deliberately (time-major for motion, or a space-filling/Hilbert order for spatial coherence) and consider a bidirectional or state-carrying scan since offline seg (unlike their causal classification) can look ahead.
- Ablation shows the SSM is doing the heavy lifting (82.1% -> 57.5% without it) precisely because it supplies GLOBAL temporal context — this validates the repo's finding that a global-context/presence signal, not local motion, is the real FP suppressor. An SSM scan over the whole window is a principled replacement for the coarse /8 dense-context bottleneck.
- Watch the two stated failure modes directly relevant here: (a) once explicit temporal modeling is added the model overfits small datasets — matches the 3-subject LOSO ceiling, so pair the SSM with strong cross-subject aug/regularization; and (b) FPS + window aggregation adds latency and breaks streaming — for real per-event/low-power operation prefer micro-window streaming with a persistent SSM state carried across windows rather than re-FPS-ing each window.


### 5. Serialized Point Cloud Mamba Segmentation Model ("Serialized Point Mamba") — arXiv:2407.12319v1. A Mamba/SSM-based point-cloud semantic+instance segmentation network built on a PTv3-style serialization idea. NOTE: this is a point-cloud (not event-camera, not per-event) segmenter; it is relevant to your task by analogy as an SSM alternative to the graph/sparse-conv path.
<https://arxiv.org/html/2407.12319v1>

**Architecture:** U-Net encoder-decoder with 5 encoder stages, no attention. The core is a "Selective SSM" (Mamba/S6) sequence model applied to points that have been linearized into a 1D sequence by space-filling curves. Per-stage block order is: Grid-Pooling -> Conditional Positional Encoding (CPE) -> LayerNorm -> Selective SSM -> LayerNorm -> MLP. CPE is a sparse submanifold conv residual: x = x + norm(SubMConv3d(x)), applied before each Mamba block to re-inject geometric/positional structure that the 1D serialization loses. Mamba blocks per stage: (2,2,2,6,2). Channels: full model (32,64,128,256,512); "tiny" variant keeps width constant at (192,192,192,192,192). Two sizes: tiny ~16M params, full ~50M params. Bidirectional Mamba: one branch runs the sequence forward, a second branch reverses it; outputs are gated and concatenated so each point sees both scan directions.

**Graph / SSM specifics:** SSM/scan-based (not a graph net). Sequence is built by SERIALIZATION along space-filling curves: four orders — Z-order, Trans-Z, Hilbert, Trans-Hilbert. A different one of these four orders is used at each successive layer/block so that locality broken by one curve is recovered by another (curves are complementary). Sequence is chunked into fixed subsequences of length 1024 points per Mamba block; a leftover tail too short to fill 1024 is padded by replicating points from the nearest preceding subsequence (a noted duplication artifact). State: input-dependent selective state (S6), so state transition/gates are data-conditioned rather than a fixed state dim. Downsampling is GRID POOLING (voxel-grid pooling) rather than kNN/radius neighbor queries — no explicit edge radius or kNN graph is ever constructed. Complexity is linear in sequence length (vs quadratic attention).

**Head & context injection:** Standard U-Net decoder producing per-point class logits (semantic seg); for instance segmentation it plugs into a PointGroup head. The paper is thin on decoder specifics (skip/unpool mechanics not detailed). Critically for your design: there is NO global-context token and NO global pooling/aggregation. All "context" is purely implicit, arriving through (a) hierarchical grid-pooling across the 5 stages growing the receptive field, and (b) the SSM's linear recurrence carrying state along the serialized sequence. This is the opposite of your repo's dense-global-context / presence-gate approach.

**Complexity & latency:** Linear-time in #points (SSM), no quadratic attention. Reported on ScanNetv2 (Table 6): full model 50M params, train latency 206ms / train mem 5.6G, inference latency 99ms / inference mem 4.4G. Tiny model 16M params, train 196ms / 10.8G, inference 169ms / 9.6G (the constant-width tiny is actually heavier at inference — attributed to bidirectional overhead). Authors claim lowest latency among compared models with a reasonable memory footprint.

**Accuracy & datasets:** Semantic segmentation mIoU: ScanNet val 76.8% (PTv2 75.4%); nuScenes 80.6% (PTv2 80.2%); S3DIS Area5 70.6% (UNDERperforms PTv2 71.6%). Instance seg ScanNetv2 with PointGroup head: 40.0 mAP (PTv2 38.3). Datasets: ScanNet (indoor), S3DIS (indoor, larger scenes), nuScenes (outdoor LiDAR). All are static 3D point clouds — no event-camera / temporal data.

**Pitfalls / limits:** (1) Large scenes hurt: on S3DIS (much larger than ScanNet) it loses to PTv2 — long serialized sequences degrade SSM modeling; your event windows can be large N. (2) Serialization is lossy: a single space-filling curve breaks 3D locality (points adjacent in 3D can be far in 1D), which is why they alternate 4 curve orders and re-inject CPE each block — mandatory, not optional. (3) Subsequence padding by replicating neighboring points introduces duplication artifacts. (4) Bidirectional scan doubles cost and unexpectedly makes the tiny model slower at inference. (5) No global context / null-state — likely a weakness for your static-window false-positive problem, which your notes show needs an explicit presence gate. (6) It is per-POINT on static clouds, not per-EVENT streaming; there is no temporal axis, no recurrence across windows, and no online/causal constraint.

**Design takeaways:** - Serialization + SSM is a real alternative to your spconv/GNN backbone: linearize events with a space-filling curve over (x,y) or (x,y,t) and run a selective SSM in linear time — but you MUST preserve the time axis, so serialize within-time-bin or use a (t-major, then Hilbert-in-space) order rather than a pure 3D curve that scrambles time (mirrors your EventSparseSeg 'never collapse time' rule).
- Locality loss from 1D serialization is the central failure mode — copy their two fixes: alternate multiple complementary curve orders across successive blocks (Z / Trans-Z / Hilbert / Trans-Hilbert), and add a Conditional Positional Encoding residual (a submanifold-sparse-conv, which you already have via sparse_backend) before each SSM block to re-inject true 3D adjacency.
- Their biggest gap vs your problem is NO global context and NO null/presence state — keep your dense-global-context bottleneck and supervised presence-gate on top of any SSM core; an event SSM segmenter that only carries serialized local state will reproduce their static-scene weakness and your measured static-window false positives.
- Fixed 1024-length subsequences + tail padding is a cheap way to bound memory and get streaming-friendly chunks; for per-event streaming prefer causal (unidirectional) scan and carry SSM state ACROSS windows (your REPM/recurrent-bottleneck idea) instead of their non-causal bidirectional scan, which doubles cost and isn't online.
- Grid-pooling downsampling with no kNN/radius query keeps the pipeline neighbor-query-free and linear — attractive for low-power/1ms goals — but note their receptive field then depends entirely on pooling depth + sequence recurrence, so budget enough stages (they use 5, deepest block count 6 at the coarsest stage) to reach whole-hand scale.
- Long sequences degrade quality (S3DIS regression): cap events-per-window or hierarchically pool early so the SSM sees a shorter effective sequence; don't feed a raw 100k-event stream to a single scan.


### 6. PointMamba: A Simple State Space Model for Point Cloud Analysis (Liang et al., 2024). Task: 3D point-cloud classification, part segmentation, and few-shot learning. It is an SSM (Mamba) model, NOT a graph network — it is the canonical reference for how to turn an unordered 3D point set into a 1D sequence for a selective state-space scan.
<https://arxiv.org/html/2402.10739v5>

**Architecture:** Pipeline: raw points (M=1024, xyz only) -> Farthest Point Sampling to n=64 key points -> kNN grouping (k=32 neighbors/key point, coords normalized by subtracting the key point = relative coords) -> lightweight PointNet patch embedding -> 64 tokens. Tokens are serialized TWICE via two space-filling curves (Hilbert and Trans-Hilbert) and concatenated into one long ordered sequence. A tiny 'order indicator' (learnable per-order scale gamma + shift beta, ~1.5k params, Eq.3) tags which serialization each token came from so the unidirectional scan can tell the two orderings apart. Backbone = N=12 plain (non-hierarchical, isotropic) Mamba blocks, hidden dim C=384. Each block: LayerNorm -> selective SSM (with an internal depthwise conv) -> gated MLP, residual connections. Pretraining decoder = 4 Mamba blocks + linear head reconstructing masked point coords under Chamfer Distance (serialization-based masked modeling, mask ratio 60%, on ShapeNetCore). Total 12.3M params.

**Graph / SSM specifics:** SSM, not graph. Sequence built by concatenating a Hilbert-ordered copy and a Trans-Hilbert-ordered copy of the 64 tokens (dual space-filling curves; Z-order tested and underperformed; random order worst). Unidirectional (causal) scan only — bidirectionality is emulated by the two curve orders rather than a reverse pass. Backbone depth N=12, hidden C=384. Internal Mamba SSM d_state / expansion factor / conv kernel are NOT stated in the paper; they use vanilla Mamba defaults (conventionally d_state=16, expand=2, dw-conv kernel=4). Order indicator adds learnable affine (gamma, beta) per serialization, ~1.5k params.

**Head & context injection:** Classification head: pool token features (concat of mean+max over the sequence per the Mamba/Point-MAE convention) -> MLP. Part-segmentation head: the paper is deliberately thin here (a stated limitation) and follows the Point-MAE recipe — take intermediate token features from several encoder layers, propagate the 64 key-point features back to all 1024/2048 points by nearest-neighbor/feature-propagation interpolation, concatenate multi-level features plus a global pooled feature and the one-hot object class label, then a per-point MLP predicts part logits. Global context injection is INHERENT to the SSM: the recurrent hidden state accumulates information along the scan, so later tokens (including the second, Trans-Hilbert ordering) see a summary of everything scanned before them — the paper argues in App. A.2 this is why the dual-order concatenation matters (each order gets global context from the other).

**Complexity & latency:** Linear O(n) in sequence length vs Transformer O(n^2). FLOPs 3.1G on ScanObjectNN (vs 4.8G Point-MAE). At sequence length 32,768: ~30.2x faster inference, ~24.9x less memory, ~5.2x fewer FLOPs than Point-MAE. 12.3M params (vs 22.1M Point-MAE, 29.2M PointGPT-S). No absolute ms/throughput on event-scale streams is reported.

**Accuracy & datasets:** ScanObjectNN OBJ-BG/OBJ-ONLY/PB-T50-RS = 94.32 / 92.60 / 89.31%. ModelNet40 (1024 pts) = 93.6% (Point-MAE 93.2%). Few-shot 5-way 20-shot = 96.9±2.0%. ShapeNetPart part segmentation = 86.2% instance mIoU. Datasets: ShapeNetCore (pretrain), ScanObjectNN + ModelNet40 (cls), ShapeNetPart (seg).

**Pitfalls / limits:** (1) Serialization is load-bearing and fragile: a single curve is not enough, random order collapses accuracy, and the whole design hinges on hand-chosen Hilbert/Trans-Hilbert curves. (2) Unidirectional scan means a token's context depends on its position in the curve — early tokens are context-starved; the dual-order concat is a patch, not a true bidirectional fix. (3) Isotropic/plain 12-block stack has NO spatial hierarchy or multi-scale receptive field — segmentation (which needs fine + global) is the weakest task and its head is barely described. (4) Everything operates on 64 FPS key points; the model itself is coarse and relies on an external feature-propagation/interpolation step to reach per-point resolution. (5) xyz-only, static single-cloud, no temporal/streaming component. (6) Paper omits SSM d_state/expand/kernel, so reproducing exact capacity requires assuming Mamba defaults.

**Design takeaways:** - Serialization order IS the architecture for an SSM segmenter. For event streams you already have a natural, physically meaningful scan axis — TIME — so a per-event SSM can scan in true event order instead of inventing Hilbert curves. But PointMamba's lesson is that ONE order starves context: pair the temporal scan with a second spatial serialization (e.g. Hilbert/Z-order over (x,y), or a reverse-time pass) and tag each with a learnable order-indicator affine so the recurrent state can disambiguate them.
- Bidirectionality matters more than depth for segmentation. PointMamba is unidirectional and its seg head is its weakest result; a per-event SEGMENTER (dense per-event labels, not one cls token) should use a bidirectional or dual-order scan so every event sees both past and future context — but keep a causal-only variant available for streaming inference (this repo already made 'keep the causal predictor at inference' a design rule).
- Decouple the coarse backbone from per-event resolution. PointMamba runs the SSM on only 64 FPS key points and interpolates back — cheap but blurry, and exactly the 'fuzzy edges / merged fingers' failure this project keeps hitting. For per-event seg, either run the SSM at (or near) full event rate, or if you voxel/key-point downsample, make the up-propagation learned and feature-rich (multi-level concat + relative-coord kNN) rather than nearest-neighbor.
- Global context comes free from the recurrent state, but only forward along the scan — so inject an EXPLICIT global/presence summary too. PointMamba leans entirely on hidden-state accumulation; this repo's own measurements show a supervised presence-gate / dense global-context token is what actually suppresses static false positives. Concatenate a pooled global feature (and a presence logit) into the per-event head rather than trusting the scan alone.
- Use relative, key-point-centered coordinates and lightweight PointNet patch embeddings as the tokenizer — this normalization is cheap and is what lets the SSM generalize across positions; for events, embed a small local (x,y,t,polarity) neighborhood per token the same way instead of feeding absolute coords.
- Linear O(n) scan is the real prize for events: PointMamba shows ~30x speed / ~25x memory wins over attention at 32k-length sequences, and event windows are far longer than 64 tokens. An event-native SSM can process the whole window in one linear pass — but budget the SSM d_state (Mamba default 16 is small); for dense per-event discrimination consider a larger state and a dual (spatial+temporal) scan rather than more isotropic depth.


### 7. AEGNN: Asynchronous Event-based Graph Neural Networks — Simon Schaefer, Daniel Gehrig, Davide Scaramuzza (CVPR 2022). Processes an event stream as an evolving spatio-temporal graph via a GNN, trained synchronously but run asynchronously at test time by recomputing only the subgraph a new event touches.
<https://arxiv.org/abs/2203.17149>

**Architecture:** Each event becomes a graph node at position (x_i, y_i, t*_i) with t*_i = beta * t_i (temporal axis rescaled to be commensurate with pixel spacing). Node feature = event polarity p_i (1 channel in); edge features = normalized relative spatio-temporal positions feeding a B-spline kernel. Backbone = 7 SplineConv (B-spline continuous-kernel) graph-conv blocks, each ELU + BatchNorm, message passing with summation aggregation. Channel progression (recognition): (1,8,16,16,16,32,32,32), spline kernel size k=2; (detection): (1,16,32,32,32,128,128,128), k=8. Two graph max-pooling layers interleaved (at blocks 5 and 7). Heads: classification = global pool -> FC to class logits; detection = a YOLO-style head (grid cells predicting class, bbox offset/shape, confidence, with weighted multi-term loss).

**Graph / SSM specifics:** Graph construction: radius-R connectivity in normalized (x,y,t*) space with a hard max-degree D_max cap per node to bound sparsity/compute; edges directed forward in time so the graph is causal/incremental. Input events uniformly subsampled by factor K=10 to fight overfitting and cut node count. Pooling = voxel-grid max pooling on a 12x16x16 (t x y x x) spatio-temporal grid: one representative node kept per occupied voxel, coarsening the graph twice. Async update rule: adding one event only dirties its 1-hop neighborhood at layer 1, propagating to a k-hop neighborhood at layer k, so activations are recomputed only along the affected cone rather than over the whole graph — mathematically identical output to the synchronous forward pass.

**Head & context injection:** Global context is injected only weakly and late: a global pooling over surviving nodes feeds the classification FC. There is no dense per-node/per-event output head — the model emits one graph-level label (classification) or a small set of boxes (YOLO head). Spatial reach for any node's decision comes purely from stacked local message passing plus the two voxel-pool coarsenings (larger receptive field via graph depth, not a global token or attention). This is the main gap for per-event segmentation: nothing produces a row-aligned logit per input event.

**Complexity & latency:** Reported per-event cost: N-Caltech101 recognition 7.31 MFLOPs/event, N-Cars 0.47 MFLOPs/event; detection 7.41 (N-Caltech101) and 5.26 (Gen1) MFLOPs/event. Async recomputation gives up to ~11x lower theoretical compute vs a dense/synchronous GNN and up to ~8x lower theoretical latency. Wall-clock (25,000 events): dense GNN 1014 ms vs async 129 ms (~8x). Caveat: their Python/CUDA implementation is only ~1.5x faster than an optimized dense CNN in practice; the FLOP win needs specialized hardware (FPGA/IPU) to convert into real latency — which later work (EvGNN accelerator) confirms.

**Accuracy & datasets:** Recognition: N-Caltech101 accuracy 0.668; N-Cars 0.945. Detection (mAP): N-Caltech101 0.595; Prophesee Gen1 (automotive) 0.163. Datasets are N-Caltech101, N-Cars, and Gen1. Numbers are competitive-but-not-SOTA at drastically lower per-event compute; e.g. AsyNet beats it by ~4.8 mAP on N-Caltech101 detection.

**Pitfalls / limits:** Low absolute Gen1 detection mAP (0.163) — the async-GNN accuracy trails dense CNN detectors on hard real scenes. Voxel-grid pooling design was not ablated (authors flag it as open). Uniform K=10 subsampling is crude; smarter sampling gave only marginal gains at higher cost. The theoretical FLOP/latency advantage does not materialize on GPU (only ~1.5x over an optimized CNN) without custom hardware. D_max/radius are hard hyperparameters that trade sparsity against connectivity. No per-event/dense output — it is a graph-level classifier/detector, so per-event segmentation is not demonstrated. Async correctness assumes a static trained graph topology and forward-in-time edges.

**Design takeaways:** - Rescale time explicitly (t* = beta*t) so a single radius-R / kNN neighborhood is meaningfully isotropic in (x,y,t); beta is the key knob that decides whether an event connects to spatial neighbors or to its own temporal history — expose it as a first-class hyperparameter in any per-event SSM or graph segmenter.
- Bound per-node fan-in with a hard max-degree (D_max) and radius rather than dense/kNN-only graphs: it caps worst-case compute per event and is what makes true asynchronous, incremental updates tractable — a per-event streaming segmenter should preserve this locality budget.
- Exploit the async 'dirty-cone' update: a new event only invalidates a k-hop neighborhood at depth k. A per-event segmenter can update just the affected events' logits instead of re-running the whole window, but this REQUIRES forward-in-time (causal) edges and a fixed trained topology.
- AEGNN's biggest missing piece for our task is a dense per-event head and strong global context — local message passing + voxel pooling alone under-segments. A capable per-event segmenter should add a genuine global/presence token (or a state-space bottleneck that carries scene-level context) fused back to every event, not rely on receptive-field growth from depth.
- Voxel-grid max pooling (12x16x16) is an effective, cheap graph coarsener that keeps the time axis — mirror this (spatial-heavy, time-preserving downsampling) rather than collapsing time; it matches this repo's documented spconv failure mode.
- Treat the FLOP win as hardware-conditional: async GNN/SSM efficiency only pays off on FPGA/IPU-style hardware; on GPU a dense representation is competitive. Choose the async/graph formulation for deployment/low-power goals, not for GPU training speed.


### 8. Gehrig & Scaramuzza, "Pushing the Limits of Asynchronous Graph-based Object Detection with Event Cameras" (a.k.a. EAGR / Efficient Asynchronous Graph Neural Networks), 2022. Event-native GNN object detector, not a segmenter — but the async graph machinery is directly transferable to per-event dense labeling.
<https://arxiv.org/abs/2211.12324>

**Architecture:** Events are modeled as a spatiotemporally evolving DIRECTED ACYCLIC graph. Each event is a node n = (x/W, y/H, beta*t) with beta = 1e-6 mapping microsecond timestamps into the normalized spatial range. Edges are built by radius search: (i,j) in E iff ||n_i - n_j||_inf < R with R = 0.01, capped at 16 max neighbors per node, and directed by time (t_i < t_j) so the graph is a DAG. Backbone = 5 residual blocks alternating with max-pool layers, 13 convolution layers total (roughly 2x prior async GNNs: AEGNN 5, NVS-S 7). Multiple conv layers precede each pool ("input block" of ~3 layers, +1.8 mAP vs single). Detection head is YOLOX-style multi-scale, emitting per-node bbox(4) + class scores + objectness(1). Model families Nano/Small/Medium/Large scale channel width.

**Graph / SSM specifics:** Convolution = Look-Up-Table Spline Convolution (LUT-SC): trained as ordinary SplineConv (B-spline basis, degree d=1, k=5 grid points) over relative 2D spatial offsets, then at deployment the continuous kernel is discretized and cached as a lookup table indexed by rounded relative position, and BatchNorm is fused into the weights. This cuts per-message cost from ~151 MFLOPS to ~4 MFLOPS. Pooling is over voxel grids (g_x, g_y, g_t)_i = (56/2^i, 40/2^i, 1) at layer i — note g_t = 1 always: time is aggregated ONCE at the input and never re-binned, which is the single most important design choice (removing early temporal aggregation drops 30.4 -> 21.2 mAP, i.e. -10.6 to -9.2 mAP). Directed Event Graphs (DEGs) keep k-hop subgraph sizes bounded/constant in early layers (+1.8 mAP at near-zero cost). Async mode: a new event triggers only LOCAL node updates; position rounding lets LUTs be reused, and node-update pruning skips a node's downstream work when it fails post-pool change conditions, skipping up to 73% of low-layer compute.

**Head & context injection:** Per-node YOLOX-inspired head produces detections directly at graph nodes (bbox regression, class, objectness). Global/multi-scale context is injected purely through the hierarchical max-pooling pyramid: repeated spatial-only voxel max-pool (factor 2 in x,y each stage, time fixed at 1 bin) progressively grows each node's receptive field while the residual blocks fuse features — there is no separate global token or attention; context comes from the pooling hierarchy plus the directed temporal edges.

**Complexity & latency:** Per-event complexity (MFLOPS/event): Nano 1.36 (3.8x lower than AEGNN), Small/baseline 4.58, Large 17.4. Latency 8.4-8.46 ms per forward pass in async mode vs 30.8 ms for the equivalent dense GNN = 3.7x speedup. LUT-SC is the main lever (~40x per-message reduction); pruning skips up to 73% of lower-layer computation. Small model is up to 3.7x lower compute than async baselines while +7.4 mAP; Medium is 13% more efficient than SOTA while +11.5 mAP.

**Accuracy & datasets:** Gen1 Automotive Detection (mAP): Nano 26.3, Small 30.4, Medium 31.8, Large 32.1; beats prior async SOTA AEGNN (16.3) by up to +11.5 and edges out dense Events+YOLOv3 (31.2). N-Caltech101 (mAP): Small 70.2, Large 73.2 vs AEGNN 59.5. Datasets used: Gen1 Automotive and N-Caltech101 (also referenced 1Mpx-scale context).

**Pitfalls / limits:** Recurrent DENSE detectors still win on absolute accuracy: RED and ASTMNet beat the Large model by 7.9 and 14.6 mAP respectively — the async GNN trades accuracy for latency/compute and has NO temporal memory across windows (feed-forward only), which the authors flag as the obvious next direction. Other constraints: LUT caching depends on rounding node positions to a discrete grid (quantization of the spatial coordinate); g_t=1 means all within-window temporal structure is collapsed immediately (great for their detection task, a real risk for tasks needing fine intra-window timing); the radius R=0.01 / 16-neighbor cap fixes locality and can starve context for sparse regions; pruning correctness relies on the DAG/time-ordering assumption.

**Design takeaways:** - Quantize + cache the kernel, not the graph: LUT-SC shows a continuous-coordinate spline conv can be trained densely then deployed as a position-indexed lookup table (~40x cheaper per message, BN folded in). A per-event SSM/graph segmenter can adopt the same train-continuous / deploy-discrete trick to hit sub-10ms async budgets without retraining a separate cheap model.
- Aggregate time ONCE, keep space fine: their biggest single win (~+10 mAP) is collapsing the time axis to a single bin at the input and pooling only spatially thereafter. This is the direct inverse of this repo's sparse-path invariant (EventSparseSeg deliberately PRESERVES the time axis) — so the lesson is task-dependent: for detection collapse time early, but for per-event segmentation where each event needs its own label, DO keep the time axis and instead push context through spatial pooling, matching your existing stride=(1,2,2) choice.
- Use a directed, time-ordered graph with a hard neighbor cap: DAG edges (t_i<t_j, ||.||_inf<R, <=16 neighbors) bound k-hop subgraph size, enable async local-only updates, and add +1.8 mAP nearly free. A per-event segmenter should build causal directed edges so inference can be streamed event-by-event with pruning rather than recomputed per window.
- Inject global context via a spatial pooling pyramid, not a global token: EAGR gets long-range context purely from hierarchical max-pool (spatial /2 per stage, time fixed) plus residual blocks. For a per-event head, upsample/scatter pooled features back to event rows (row-aligned to labels) to give each event multi-scale context cheaply.
- Depth matters and is affordable once messages are cheap: they doubled depth to 13 conv layers / 5 residual blocks and stacked ~3 convs before each pool (+1.8 mAP) — cheap conv (LUT) is what unlocks the depth. Prefer more layers of cheap local ops over a few expensive global ops.
- Async pruning gives large real speedups but assumes discretized positions and temporal ordering: skip-on-no-change pruning cut up to 73% of low-layer compute. A streaming per-event segmenter can exploit the same redundancy, but must round coordinates and respect causal ordering — and note the honest ceiling: feed-forward async GNNs still trail RECURRENT dense models by 8-15 mAP, so add cross-window recurrence/memory (a GRU/SSM state) if accuracy is the priority.


### 9. EvGNN: An Event-driven Graph Neural Network Accelerator for Edge Vision (Yufeng Yang, Adrian Kneip, Charlotte Frenkel; v2 Feb 2025). NOTE: this is a GRAPH-based per-event accelerator for classification (N-CARS), not an SSM/segmentation paper. It is still directly relevant to designing an event-native per-event segmenter because it specifies a fully event-driven, causal, 1-hop directed-graph pipeline that emits a decision per incoming event.
<https://arxiv.org/abs/2404.19489>

**Architecture:** A 4-layer directed dynamic GNN run per-event. Channel widths: input -> 16 -> 32 -> 32 -> 2 (output). Convolution = simplified PointNetConv: per edge, concatenate absolute relative spatial offset (|dx|,|dy|) with the neighbor node feature, apply a shared linear transform, then MAX-aggregate over neighbors (max-relative style, permutation-invariant, no edge attributes stored). Derived from AEGNN but stripped: NO residual connections, NO graph pooling, batchnorm folded into linear layers, INT8 post-training quantization. Param budget: 121.6 kB (AEGNN) -> 26.4 kB FP32 -> 6.6 kB INT8 (5x smaller; PointNetConv is 6.3x cheaper than SplineConv). Four HW modules mirror the model: graph-building, graph-convolution (layer-parallel MatVec units), graph-readout, FC head.

**Graph / SSM specifics:** GRAPH construction (no SSM/scan). Directed dynamic graph: edges point ONLY from past nodes to the newly arrived event (causal) so edges need not be stored. Neighbor search is spatiotemporally DECOUPLED into a prism using L1 (Manhattan) distance to avoid sqrt: spatial gate |dx|+|dy| <= r_s, independent temporal gate dt <= r_t. Lookup uses per-pixel event QUEUES: one FIFO per pixel (grid 120x100 for N-CARS), each holding up to 16 entries of (timestamp, polarity, event index). Spatial search selects candidate pixel queues within r_s; temporal search keeps those with dt <= r_t. Hard cap of 16 neighbors per event with early stopping. Strictly 1-HOP (only direct neighbors of the new event), removing AEGNN's K-hop expansion. Layer-parallel scheme runs all 4 conv layers concurrently rather than sequentially (6.9us -> 2.6us, 2.5x).

**Head & context injection:** Per-event output = a 2-class logit from an FC head. Global context injected via a GRID-BASED readout: 120x100 field tiled into an 8x7 grid of 16x16-pixel patches, node features MAX-pooled within each cell, giving a fixed 56-dim (8x7) global descriptor consumed by the FC head. Context is thus a coarse spatial max-pool, not a recurrent token or attention. Classification is reliable after ~50 accumulated events.

**Complexity & latency:** 0.07 MFLOPs/event (vs AEGNN 0.6, ~8.5x cheaper). Per-event latency 16 us on Xilinx KV260 FPGA; 10.7 us on simulated 28nm ASIC at 305 nJ/event. On-chip memory 1.76 MB, dominated by event queues (UltraRAM 75% util); DSPs 18.3%, LUTs 26.4%. Layer-parallel cuts the conv portion 2.5x (6.9->2.6 us).

**Accuracy & datasets:** Dataset: N-CARS binary car recognition (event camera). Splits: 13,108 train / 2,314 val / 8,607 test. Accuracy 88.0% software FP32 (beats AEGNN 86.7%) and 87.8% hardware INT8 (0.1% drop). Single-label recognition benchmark, NOT segmentation/dense-labeling.

**Pitfalls / limits:** 1) Event-queue storage scales QUADRATICALLY with sensor resolution; QVGA/HD needs off-chip storage (~10% latency/energy overhead). 2) DRAM bandwidth for feature/weight transfers dominates latency, scales linearly with layer size; authors suggest neighbor-feature caching. 3) Hard 16-neighbor cap can starve high-degree (dense-event) nodes -- a real risk for dense hand-event windows with far more than 16 neighbors. 4) Hard-specialized to 1-hop; K-hop receptive fields need redesign. 5) Evaluated only on binary classification -- per-event dense segmentation with this pipeline is unproven. 6) Coarse 8x7 grid readout is too low-resolution to be the sole context source for spatial segmentation.

**Design takeaways:** - Make the graph directed and causal (past->new only) so edges are never stored and inference is a pure streaming per-event update; this composes cleanly with a recurrent/SSM global carry-slot.
- Decouple spatial vs temporal neighbor search with L1 gates (|dx|+|dy|<=r_s, dt<=r_t) instead of a Euclidean spatiotemporal ball: sqrt-free, cheap, and lets you tune finger-scale spatial locality independently from motion time-constants.
- Prefer a max-relative / simplified-PointNet edge op (concat relative offset with neighbor feature -> linear -> max) over SplineConv: ~6x fewer params, permutation-invariant, quantization-friendly, and translation-equivariant local geometry for free.
- The fixed 16-neighbor cap is the key scaling knob AND the main danger for dense event streams: naive early-stop silently drops the hand signal, so sample neighbors deliberately (e.g. stratified across time bins) rather than truncating.
- A coarse grid max-pool is enough for one global label but too coarse for segmentation; pair the local 1-hop graph with a real global-context/presence pathway (multi-scale pooled context or a persistent global-state token / presence gate) so each event's label can be vetoed by scene-level evidence -- the same FP-suppression lever seen in the repo's SSM-stream work.
- Pipeline network depth over the event stream (layer-parallel, all layers advance per event) instead of running a multi-layer pass to completion per event: turns a deep model into a low-latency streaming segmenter (2.5x here).


### 10. "Event-based Graph Representation with Spatial and Motion Vectors for Asynchronous Object Detection" — Verma, Vaghela, Chakravarthi, Chanda, Yang (Arizona State University). A sparse asynchronous event-based GNN for object detection (per-event/point-wise head, not semantic segmentation), 5.6M params.
<https://arxiv.org/html/2507.15150v1>

**Architecture:** Graph Neural Network (NOT an SSM). Core is a stack of 8 SMVL (Spatial and Motion Vector Learning) blocks with output channels (16,16,32,32,64,64,128,128). Each SMVL block has two INDEPENDENT parallel pathways operating on two different neighborhoods of a multigraph: (1) SSL = Spatial Structural Learning: B-spline convolution with an anisotropic k×k×1 kernel (e.g. 8×8×1) applied on the 2D spatial (x,y) plane only — collapsing the time dimension in the kernel is claimed to cut compute up to 87.5% for k=8. (2) MVL = Motion Vector Learning: GATv2 multi-head attention (4 heads in backbone, 1 head in detection head) over temporal neighbors, with attention guided by motion/velocity edge features. Pathway fusion is deliberately lightweight: concatenation + MLP (they avoid cross-attention on purpose). Detection head compresses to 64-dim then splits into classification (n+1 classes) and regression ({x',y',w',h'} + IoU confidence) branches; post-processing = active-region pooling of spatio-temporally proximal events + NMS.

**Graph / SSM specifics:** Multigraph with DECOUPLED spatial vs temporal edges, both built via an ellipsoidal (radius) neighbor rule ||Δv_xy||/R_XY + |Δt|/R_t < 1 with causal ordering t_i<t_j. Spatial edges: R_XY = 4% of input dimension, R_t = 5ms, max 16 neighbors/node. Temporal edges: R_t = 40ms, R_XY = 1% of input dimension, max 12 neighbors/node (inverted orientation — long time, tight space). Node init features = (x,y,t,p) normalized to {-1,+1}. Spatial edge features = (Δx,Δy,Δt); temporal edge features = (Δx,Δy,Δt,Δx/Δt,Δy/Δt,Δp) i.e. explicit velocity + polarity change. No serialization order (it is a graph, not a scan). Graph is built on-the-fly rather than pre-stored (they note most prior work pre-stores graphs).

**Head & context injection:** Point-wise / event-level sparse head that preserves sparsity: per-event classification (n+1 = objects + background) and per-event bbox regression with offset normalization x'=(x_gt−x_pos)/w_0, w'=log(w_gt/w_0), plus an IoU-confidence output. Global/scene context is injected implicitly through the temporal MVL pathway's long-range (R_t=40ms) attention edges and progressive channel widening across the 8 layers — there is NO explicit global token, presence gate, or dense-context bottleneck; aggregation to object level happens only at post-processing via active-region pooling + NMS.

**Complexity & latency:** 5.6M parameters. Per-event compute: 4.5 MFLOPs/event on Gen1 (304×240), 26.1 MFLOPs/event on eTraM (1280×720). Claims ~1000× fewer MFLOPs/event than Transformer+RNN dense methods and 5× speedup over AEGNN. Latency on A30 GPU with a 4000-node graph: 18.1ms serial (SSL then MVL) vs 17.7ms with the two pathways run in parallel. Training: ~2 days on one H100; AdamW lr 4e-4, wd 1e-4, OneCycleLR 175k steps, batch 24, 100ms time window.

**Accuracy & datasets:** Gen1 Automotive (39h, 304×240, 2 classes, 20Hz labels): mAP 0.371, reported +21% over AEGNN and >6% over DAGr. eTraM (10h, 1280×720, 8 classes, 30Hz labels, ~2M boxes): mAP@50 0.431, +25% over baseline. Metric = mAP at varying IoU thresholds. Task is detection, not segmentation.

**Pitfalls / limits:** (1) Memory bottleneck: irregular non-contiguous node-edge adjacency gives poor memory access on hardware built for contiguous storage — the fundamental graph limitation. (2) Scaling: benchmarking on high-res data (e.g. 1Mpx Automotive) is hard due to memory/compute of the graph. (3) Preprocessing burden: on-the-fly graph construction is nontrivial; most prior works pre-store graphs. (4) The anisotropic k×k×1 spatial kernel deliberately drops in-kernel time modeling, pushing ALL temporal reasoning onto the GATv2 pathway — a design coupling risk. (5) It is a detection head + NMS pipeline, so there is no dense per-pixel/per-event semantic label; adapting to segmentation would replace the box regressor.

**Design takeaways:** - Decouple space and time into two neighborhoods, not one metric. Their strongest idea: a spatial graph that is tight in xy / short in t (4%, 5ms, 16 nbrs) plus a SEPARATE temporal graph that is tight in xy / long in t (1%, 40ms, 12 nbrs). For a per-event SSM/graph segmenter this maps cleanly to (a) a local spatial-coherence branch and (b) a long-horizon motion branch — mirrors this repo's own finding that local motion alone can't veto dense noise; the two-scale split is what gives figure/ground.
- Put velocity in the EDGE/transition features, not just raw coordinates. Their temporal edges carry (Δx/Δt, Δy/Δt, Δp) — explicit normal-flow-like velocity and polarity change. An event-native SSM should feed per-event velocity/normal-flow and Δpolarity into the state-transition input, since this repo already measured that plain SAE plane-fit motion is non-discriminative — pairwise relative velocity on edges is a richer, still-cheap alternative.
- Factorize the operator to kill the time-collapse failure. They use an anisotropic k×k×1 spatial conv (space only) fused with attention (time only) rather than a full 3D op — directly analogous to EventSparseSeg's stride=(1,2,2) 'never collapse time' rule. For an SSM: keep a spatial mixing op and a temporal scan as separate factors and fuse by concat+MLP, avoiding an expensive joint 3D/cross-attention core.
- Prefer lightweight concat+MLP fusion over cross-attention. They explicitly reject cross-attention between the spatial and motion pathways to save compute and report ~1000× fewer MFLOPs/event than dense Transformer+RNN. A per-event segmenter under a latency budget should fuse branches with concat+MLP and reserve attention for the temporal branch only.
- Keep the head strictly point-wise to preserve sparsity and async operation. Classification + regression are computed per-event with offset/log normalization, and only pooling+NMS aggregate at the end. A per-event segmenter should keep one logit per event (as this repo's SparseEventBatch already does) and do any spatial-coherence cleanup as post-processing, not inside the backbone.
- Budget for the graph memory wall; radius caps (max 16/12 neighbors) are load-bearing. Their headline limitation is irregular non-contiguous adjacency and poor scaling to 1Mpx. If low-power/async streaming is the goal, this is the argument FOR an SSM/scan formulation (contiguous, linear-time, no adjacency storage) over a GNN — adopt the decoupled two-scale motion idea but realize it as ordered scans rather than stored graphs.
- On-the-fly graph/state construction and causal ordering (t_i<t_j) are required for true async inference; pre-storing graphs (which they flag as common prior practice) breaks streaming — an SSM's inherently causal recurrence gives this for free.


### 11. "Graph-based Asynchronous Event Processing for Rapid Object Recognition" — Yijin Li, Han Zhou, Bangbang Yang, Ye Zhang, Zhaopeng Cui, Hujun Bao, Guofeng Zhang (State Key Lab of CAD&CG, Zhejiang University; ICCV 2021 line of work). NOTE: this is an asynchronous event-graph CLASSIFIER (object recognition), not a per-event segmenter — but its incremental/async graph mechanics are the load-bearing part for a per-event design.
<https://arxiv.org/abs/2308.14419>

**Architecture:** Events are treated as a spatiotemporal point cloud (x, y, t) and turned into a radius-neighborhood graph. Nodes = events; edges connect events within a spatial radius R subject to a maximum node degree D_max; edge attributes are relative Cartesian coordinates e_ij between linked nodes. The temporal axis is upscaled by a factor so event density is roughly uniform across x, y, t (prevents the time axis from dominating/being dominated by the spatial neighborhood test). Two backbone variants are adapted: (1) NVS — 4 stacked "GraphConv–ELU–BatchNorm" blocks followed by graph pooling, a max/mean readout to a global vector, then a fully-connected prediction head with dropout p=0.3 after the first FC; (2) EvS — adds event surface-normal attributes and filters edges to an upper-hemisphere / motion-parallel constraint (keeps only causally/motion-consistent neighbors). The graph convolution is spatial-domain message passing: (f⊗g)(i) = Σ_{j∈E(i)} h_θ(f(i), f(j), e_ij), summation aggregation. The central contribution is "Slide Convolution": an INCREMENTAL formulation f_{n+1}^{t+1}(i) = f_{n+1}^t(i) + Δ_{n+1}(i) — each new event only propagates a delta through the edges it actually touches, so the past graph's activations are cached and reused rather than recomputed per window.

**Graph / SSM specifics:** Graph (not SSM). Construction is a two-stage radius search instead of a dynamic k-d tree: Stage 1 uses a precomputed distance field over the pixel grid to gather candidate pixels within spatial radius R; Stage 2 does a binary search inside each candidate pixel's time-ordered event queue for the temporal band t0 ± sqrt(R^2 − (δx^2 + δy^2)) (i.e. the neighborhood is a spatiotemporal ball). This gives O(1) amortized insert/delete and ~50% lower query cost than a nanoflann k-d tree. Serialization order = event arrival (temporal) order; per-pixel event queues are the index structure. Backbone depth = 4 GraphConv layers (NVS). Exact numeric R, D_max, temporal-upscale factor, channel widths, and voxel-pool sizes are relegated to the supplementary and not in the HTML body. A "state-aware" MLP head maps the current graph feature to a binary "prediction is stable" flag for early recognition (stop consuming events once stable).

**Head & context injection:** Global context is injected by graph pooling + a permutation-invariant max/mean readout that collapses all node features into one global vector, which the FC classifier head consumes — i.e. context is GLOBAL-POOLED, appropriate for whole-cloud classification, NOT per-node. There is no per-event output head here (it is a classifier). The only per-event-style head is the auxiliary state-aware MLP that emits a scalar stability bit per incoming event, trained with an approximate label ("stable if the prediction equals that at the final event index"). This is the main structural gap versus a segmenter: the model has no mechanism to keep and emit a per-node label while still injecting scene-level context.

**Complexity & latency:** Slide (incremental) convolution reduces compute up to ~100x versus naive per-window recomputation. Pixel-queue radius search is ~50% cheaper than a k-d tree. CPU (i7-9700K): 16.9 ms/event with the async pipeline vs 130.4 ms baseline (~8x). Efficiency reported as FLOPs/event (Mps/ev, mega-ops per event): N-Caltech101 11.5, CIFAR10-DVS 33.2, MNIST-DVS 15.2, N-Cars 6.1. Trade-off noted: strict event-by-event processing minimizes latency but raises CUMULATIVE FLOPs; a mini-batch of ~100 events is recommended as the practical latency/throughput balance. GPU/specialized-hardware gains are stated as "expected" but not measured.

**Accuracy & datasets:** Object-recognition accuracy (EvS-S, their async model): N-Caltech101 0.761, CIFAR10-DVS 0.680, MNIST-DVS 0.991, N-Cars 0.931. Early/streaming recognition reaches 0.669 accuracy after only ~3,118 events vs 0.761 after the full ~19,154 events — most of the accuracy is available very early in the stream. All four are event classification benchmarks; no segmentation dataset is used.

**Pitfalls / limits:** (1) Approximate stability supervision — "stable if equal to the last-index prediction" — is a proxy that may not capture true convergence and can mislead the early-exit head. (2) Pure event-wise processing increases cumulative FLOPs; batching ~100 events is needed for practical efficiency (latency vs throughput tension). (3) The method requires hand-modifying the convolution operator into its incremental form; extensibility to other pooling/aggregation ops is task-specific and not free. (4) Speedups are CPU-measured; GPU/hardware benefits are only projected. (5) Global max/mean readout discards per-node identity — as-is the architecture cannot produce a dense per-event label. (6) Radius/degree caps (D_max) mean dense/bursty regions truncate neighborhoods, potentially dropping context under high event rates. (7) Key hyperparameters (R, D_max, time-scaling, channels) are in unavailable supplementary material.

**Design takeaways:** - Cache-and-delta is the core lever: for a per-event SSM/graph segmenter, keep persistent per-node (or per-cell) state and update ONLY the events/edges a new event touches (Slide-Conv style), rather than re-running a window. This is exactly the incremental-state property an SSM gives for free — an event-native recurrent scan is the natural generalization of their delta-propagation.
- Build neighborhoods with a pixel-queue + precomputed distance-field radius search (O(1) insert/delete, per-pixel time-ordered queues) instead of dynamic k-d trees; the spatiotemporal ball t0 ± sqrt(R^2 − δx^2 − δy^2) is a clean, cheap async connectivity rule to reuse.
- Normalize the time axis explicitly (their temporal upscale factor) so the x/y/t neighborhood is isotropic — for a scan-based model this is the equivalent of choosing the state time-constant / bin width so temporal and spatial context are balanced; the repo's own 'don't collapse the time axis' warning is the same lesson.
- Their global max/mean readout is the wrong head for segmentation: keep a per-node output but ALSO carry a global/context token (persistent scene state or presence gate) fused into each node's prediction — pool-for-context, decode-per-event. This directly matches the presence-gate/global-context fixes already found effective in this codebase.
- Exploit early-saturation: most discriminative signal arrives in the first ~15% of events, and they add a cheap MLP 'stability' gate. For per-event seg, a per-event confidence/stability head can early-commit stable labels and spend compute only on changing regions — but supervise it with a real convergence target, not their 'equals-final-prediction' proxy.
- Add motion/causal edge filtering (their EvS upper-hemisphere, motion-parallel constraint + surface normals) as an inductive bias — restricting message passing to motion-consistent neighbors is a lightweight way to inject the per-event motion cue that this codebase measured as the missing discriminative signal.
- Cap complexity with D_max + micro-batching (~100 events): a bounded-degree graph or bounded-window scan keeps latency flat, but watch cumulative FLOPs under bursty input; process small event mini-batches rather than one-at-a-time.


### 12. "Finding Meaning in Points: Weakly Supervised Semantic Segmentation for Event Cameras" (EV-WSSS), ECCV 2024. arXiv:2407.11216v1.
<https://arxiv.org/html/2407.11216v1>

**Architecture:** IMPORTANT MISMATCH: This paper is NOT an event-native per-event, graph, or SSM segmenter. **Complexity & latency:** No FLOPs, parameter count, or latency/throughput numbers are reported. Only hardware stated: trained on a single NVIDIA RTX 3090 with the RAdam optimizer. The backward branch is discarded at inference, so inference cost is one recurrent forward encoder + one shallow U-Net decoder over the forward voxel window.

**Accuracy & datasets:** Datasets: DDD17-Seg, DSEC-Semantic, and a newly introduced DSEC Night-Point set. mIoU results: DSEC-Semantic 45.55/45.6% (1C1C) and 51.19% (1C10C); DDD17 56.88% (1C1C) and 60.39% (1C10C); DSEC Night-Point 36.4% (1C1C). Ablation on DSEC: single-branch baseline 39.1% -> +dual pseudo-label 42.6% -> full EV-WSSS 45.6%. Fully-supervised references (upper bounds): HMNet-L 55.0% on DSEC; ESS-sup 61.37% on DDD17. 1C1C = one labeled click per present class per sample; 1C10C = ten clicks per class.

**Pitfalls / limits:** Stated challenge: BOTH the event distribution and the point supervision are sparse, so pseudo-label generation and semantic inference are hard, especially for tiny/thin objects and at night (motivating the long-window backward stream and the confidence-thresholded ignore region). The backward/future stream is a training-only oracle (needs future events), so it cannot help true streaming/online inference. Weak-label ceiling is well below fully-supervised. For our purposes the key limitation is domain mismatch: it is DAVIS/DSEC automotive dense semantic seg, dense per-pixel output, not Prophesee per-event hand/arm masks; no per-event head, no sparse-conv/graph/SSM, and no reported speed.

**Design takeaways:** - Confidence-gated pseudo-labels transfer directly to the per-event setting: compute a per-event reliability = max-softmax, set label=-1 below a threshold, and let it drop out of loss/metrics -- this is exactly the boundary_ignore / time_ignore pattern already in the sparse pipeline and validates confidence-based ignore over hard labels.
- Asymmetric dual-window (short causal window kept at inference + a longer/reversed window used ONLY in training to teach outlines and tiny structures) is a cheap way to sharpen thin fingertips without paying inference cost -- a train-only 'future' or larger-tau teacher branch distilled into the causal student, analogous to the repo's SAM2 distillation but for temporal context.
- Cross-branch mutual pseudo-labeling (each branch supervises the other) is a self-distillation regularizer that needs no extra teacher; for a per-event SSM/graph model, run a forward and a time-reversed scan and have them agree on per-event labels to regularize the state dynamics.
- Class prototypes with a memory queue (intra-sample + cross-sample + cross-branch) are how EV-WSSS injects global semantics without a global token; for a per-event segmenter, a persistent foreground/background prototype bank contrasted against each event embedding is a lighter alternative to the dense global-context bottleneck currently used to suppress static/wake false positives.
- The result that recurrent temporal ACCUMULATION (not a single voxel snapshot) drives the gains reinforces the repo's move to recurrent/SSM per-event state over frame voxels -- state carried across the window, not collapsed time.
- Honest ceiling signal: even a well-engineered dense event segmenter tops out ~45-51% mIoU vs 55-61% fully supervised, echoing the LOSO ceiling note -- expect supervision sparsity, not architecture, to bind, so budget effort on the label/ignore protocol and a train-only high-context teacher rather than on exotic backbones.


### 13. KPConvX: Modernizing Kernel Point Convolution with Kernel Attention (Thomas et al., CVPR 2024). NOTE: 2405.13194 is NOT an event-camera or graph/SSM paper — it is a point-cloud semantic-segmentation architecture (geometric kernel-point convolution). It is relevant to per-event segmentation because per-event labeling over (x,y,t) is structurally a point-cloud segmentation task.
<https://arxiv.org/html/2405.13194v1>

**Architecture:** Point-based encoder-decoder (U-Net style) built from KPConvD/KPConvX operators — NOT a GNN and NOT an SSM/scan. Structure: (1) Stem = one standard KPConv layer for a strong initial embedding; (2) Encoder = 5 levels of inverted-bottleneck blocks (block counts [3,3,9,12,3] for KPConvX-L, [2,2,2,8,2] for KPConvX-S), spatial subsampling via grid pooling between levels; (3) Decoder = grid-upsampling layers with extra conv blocks reconstructing per-point features; (4) task head. Channel widths scale by sqrt(2) not 2: [64,96,128,192,256] across the 5 levels. Core operator KPConvD is a DEPTHWISE kernel-point convolution: kernel points on a two-shell disposition [1,14,28] (center + 2 spherical shells); each neighbor is assigned to its single nearest kernel point (nearest-kernel, not summed over all kernels); one depthwise weight vector w_k in R^C per kernel point applied by Hadamard product; influence h_ik = max(0, 1 - ||x_i - x - x_tilde_k||/sigma), sigma = r, search radius r = 2.1 x grid size; fixed neighbor counts [12,16,20,20,20] per level. KPConvX adds 'kernel attention': per-kernel modulation vectors m_k generated by a 2-layer MLP (C hidden, K x C_g output, sigmoid) FROM THE CENTRAL POINT'S FEATURES ONLY, applied as grouped Hadamard (groups G=8, C_g=C/G) onto the depthwise weights before convolution.

**Graph / SSM specifics:** Neither graph nor SSM. Spatial structure is captured by FIXED kernel-point geometry rather than learned edges or a sequential scan. Neighborhoods come from radius search (r = 2.1 x grid size) with a fixed neighbor cap per level ([12,16,20,20,20]); kernel-point layout is the two-shell [1,14,28] arrangement optimized by a repulsive potential (no kNN graph, no edge features, no serialization/ordering of points). Key ordering insight relevant to any point method: KPConvX must generate its modulations in the FIXED kernel-point index order because raw neighbor order is unstable — applying learned modulations directly to arbitrarily-ordered neighbors (involution-style) fails.

**Head & context injection:** Per-point segmentation head = 2-layer MLP with 64 hidden channels -> n_class logits -> softmax, applied to the decoder's per-point reconstructed features. Classification head = global average pool over encoder output -> 2-layer MLP (256 hidden) -> n_class -> softmax. Global context is injected differently per task: for classification via global average pooling; for dense segmentation there is NO explicit global token — context propagates purely through the encoder's grid-pooling receptive-field growth and is restored per-point by the decoder's grid upsampling + skip connections. The 'attention' in KPConvX is strictly LOCAL/geometric (per-kernel weight modulation from the center point), not a global self-attention.

**Complexity & latency:** Depthwise design keeps weights at O(K x C) instead of O(K x C x O), cutting params and memory. Throughput (V100, 16 clouds x 15,000 pts): KPConvX-L 47.7 ins/s, KPConvD-L 64.1 ins/s (35% faster without attention), original KPConv 35.4 ins/s. Inference GPU memory: KPConvX-L 6.8 GB, KPConvD-L 4.6 GB vs original KPConv 12.7 GB. Params: KPConvX-L 13.5M, KPConvD-L 7.8M, original KPConv 14.1M. Complexity scales with number of points x fixed neighbor cap (radius search is the dominant cost), i.e. roughly linear in points given capped neighborhoods.

**Accuracy & datasets:** S3DIS Area 5 (semantic seg): KPConvX-L mIoU 73.5%, mAcc 78.7%, OA 91.7% (SOTA; beats PointMetaBase 72.3% mIoU). ScanNetv2 (semantic seg): mIoU 76.3% (+0.6 over OctFormer 75.7%) at 13.5M params vs competitors' 39-40M. ScanObjectNN hardest variant PB_T50_RS (shape classification): OA 88.9 +/- 0.3%, mAcc 87.3 +/- 0.5% (+1.1% mAcc over PointVector). All are static LiDAR/RGB-D point-cloud benchmarks — no event-camera data.

**Pitfalls / limits:** (1) Kernel attention is order-fragile: modulations only work applied in fixed kernel-point order, not to unordered neighbors — a warning for any per-event method that wants to modulate by neighbor. (2) Depthwise + nearest-kernel assignment trades expressivity for speed; authors note topological vs geometric feature separation is understudied and un-unified. (3) A 'double shortcut' variant gave no significant gain (dropped). (4) It is a STATIC point-cloud model: no temporal/causal/streaming mechanism, no state carry, no notion of event time or polarity, no online/low-latency streaming — it batches whole clouds. (5) No global-context token for segmentation; long-range reasoning depends entirely on pooling depth.

**Design takeaways:** - Treat per-event segmentation as (x,y,t) point-cloud seg and steal KPConvX's efficiency recipe: DEPTHWISE local operators (O(K*C) weights) + capped-radius neighborhoods give near-linear cost and 2-3x throughput/memory wins over dense conv — but note KPConvX is fully offline/static, so you must ADD the temporal-causal/streaming state that it lacks (this is exactly where an event-native SSM or recurrent bottleneck earns its keep).
- Anisotropic radius matters on the time axis: KPConvX uses radius search r = 2.1 x grid with per-level neighbor caps. For events, define neighborhoods with SEPARATE spatial vs temporal scales (a t-anisotropic radius / voxel) so 'time collapse' is avoided — mirrors this repo's stride=(1,2,2) time-preserving rule.
- Inject conditioning as a LOCAL per-kernel/per-event modulation generated from the CENTER point's features (KPConvX's sigmoid-gated grouped Hadamard), and always apply it in a STABLE canonical order (kernel index, or time-sorted for events) — modulating by raw unordered neighbor order is proven to fail. This is a cheap, DDP-safe alternative to full attention.
- KPConvX gives NO global-context token for segmentation and relies solely on pooling depth — a documented weakness for scene-level 'does a hand exist' priors. For a per-event segmenter, add an explicit global/presence state (dense-context bottleneck or presence gate) that pure local kernel/graph ops cannot provide.
- Prefer the depthwise-only variant when latency dominates: KPConvD is 35% faster and uses 30% less memory than KPConvX for only a small accuracy drop — for real-time/streaming event inference, start depthwise and add local attention only where it measurably helps.
- sqrt(2) channel scaling with an inverted-bottleneck stage stack ([2,2,2,8,2] small / [3,3,9,12,3] large) delivered SOTA at 13.5M params vs 39-40M transformers — parameter-efficient encoder shaping transfers directly to a sparse/graph event backbone, keeping the model deployable on low-power neuromorphic-adjacent hardware.


### 14. EvGNN: An Event-driven Graph Neural Network Accelerator for Edge Vision — Yang, Kneip, Frenkel (arXiv:2404.19489v2). FPGA (Xilinx KV260) hardware-software co-designed accelerator for event-driven GNNs. Task = per-event object classification on N-CARS (NOT segmentation), but its per-event graph construction and streaming execution are the transferable content.
<https://arxiv.org/abs/2404.19489 (HTML: https://arxiv.org/html/2404.19489v2)>

**Architecture:** A 4-layer event-driven GNN. Each Graph Conv Block = graph convolution + activation + batch-norm. The conv is a simplified PointNetConv variant (not SplineConv as in AEGNN): the message MLP phi is reduced to a single linear layer and the update gamma is identity — a minimal linear message + aggregation chosen for hardware cost. Nodes are events ev=(x,y,t,p). The graph is a DIRECTED DYNAMIC graph built incrementally: each incoming event is inserted, its causal neighbors located, features computed on the fly (no static batched graph). Readout = grid-based max pooling over an 8x7 grid of 16x16-px patches across the 120x100 input, then 1+ FC layers for the class prediction. INT8 on FPGA (~16us/event); 28nm ASIC projection 10.7us/305nJ/2.5mm2 per event.

**Graph / SSM specifics:** Graph, not SSM. Directed edges ONLY from past nodes to the new node (strict causality) — no future edges, enabling single-pass streaming. Neighbor search = "prism" method: spatiotemporally DECOUPLED L1 distance, spatial gate |dx|+|dy|<=r_s AND temporal gate dt<=r_t, so spatial/temporal radii are tuned independently (a rectangular x-y-t prism, not an L2 ball). Neighbors found via per-pixel "event queues" (recent events indexed by location) instead of an explicit edge list ("edge-free storage"). Fan-in capped by buffer depth D_max=16 max neighbors per event. Layer-parallel execution: since past nodes already carry all lower-layer features, a new event's layer-1..L features are computed together by reusing cached neighbor features, cutting graph-conv latency 6.9us->2.6us (2.5x).

**Head & context injection:** Per-event forward pass emits updated node features; the prediction comes from a graph readout = grid-based max pooling (8x7 grid, 16x16-px patches over the 120x100 field) then 1+ FC layers. Global context is injected purely spatially via this coarse fixed-grid pooling plus the causal receptive field grown by stacking directed single-hop layers over event history. There is NO separate global-state token and NO recurrent memory — context = pooled local features over the persistent event queue.

**Complexity & latency:** 0.07 MFLOPs/event (INT8). FPGA KV260: avg 16us/event. ASIC 28nm projection: 10.7us, 305nJ, 2.5mm2 per event. Layer-parallel scheme: graph-conv latency 6.9us->2.6us (2.5x). Cost is linear in events with bounded per-event work because fan-in is capped at D_max=16 and only single-hop updates are recomputed.

**Accuracy & datasets:** N-CARS (event-camera car vs background): 15,422 train (85/15 train/val), 8,607 test. Accuracy 88.0% software FP32, 87.8% hardware INT8 — beats AEGNN's reported 86.7% while running per-event on-chip. Only this one classification dataset; no segmentation/detection benchmark.

**Pitfalls / limits:** (1) Resolution scaling = dominant weakness: QVGA/HD gives a QUADRATIC blow-up of the per-pixel event-queue buffer. (2) Memory-bandwidth bound: feature transfer to/from DRAM scales linearly with layer size and dominates latency/energy; authors call for neighbor-feature caching. (3) Fixed 16-neighbor cap limits receptive field/expressiveness. (4) Only object-level classification with coarse grid pooling — no dense per-event head, no long-range temporal state, limited causal single-hop receptive field. Simplified linear PointNetConv trades expressiveness for hardware cost.

**Design takeaways:** - Enforce strict causal, single-hop directed graphs so a per-event segmenter runs as one streaming pass: each event reads only already-computed features of past neighbors — no re-batching — and multi-layer features can be computed layer-parallel by caching each node's per-layer output.
- Decouple spatial and temporal neighbor radii (the prism: |dx|+|dy|<=r_s AND dt<=r_t) rather than an L2 space-time ball; this matches your repo's documented lesson that collapsing/mixing the time axis is the failure mode — tune temporal reach independently of spatial reach.
- Bound per-event fan-in (D_max=16) via per-pixel event queues instead of explicit edge lists; edge-free fixed-fan-in storage keeps per-event cost O(1) and is what makes true per-event (not windowed) inference tractable.
- Budget memory as a first-class constraint: naive per-pixel queues blow up quadratically at 240x320+ DVS resolution and DRAM bandwidth scales with layer size, so plan sparse/hierarchical queues and neighbor-feature caching before scaling a graph segmenter up.
- For PER-EVENT SEGMENTATION add a dense per-event head AND inject global context beyond coarse spatial pooling — a persistent global-state token or recurrent/SSM bottleneck (as your SSM-stream and presence-gate work already do) since the plain causal single-hop graph has limited receptive field and no long-range memory.
- A minimalist linear message (single-linear-layer PointNetConv + max-aggregate) already beat SplineConv-based AEGNN at far lower cost — favor cheap per-event message functions and spend the saved compute on temporal state and context injection, not heavy per-edge MLPs.


### 15. State Space Models for Event Cameras (Zubić, Gehrig, Scaramuzza; CVPR 2024). arXiv:2402.15584v3.
<https://arxiv.org/html/2402.15584v3>

**Architecture:** SSM-ViT: an RVT-style 4-stage hierarchical backbone for event-camera object DETECTION (dense, not per-event). Each of the 4 stages is one SSM-ViT block = strided Conv (k×k) downsampling → Block-SA (windowed local self-attention) → Grid-SA (dilated/global self-attention) → an SSM temporal-mixing layer. The recurrent SSM state is carried across timesteps (one persistent SSM state per stage, reused from the previous window), replacing the ConvLSTM used in RVT. Model sizes: S5-ViT-S 9.7M, S4D-ViT-B 16.5M, S5-ViT-B 18.2M params. Detection head is YOLOX (IoU + class + regression losses, averaged over batch and sequence length).

**Graph / SSM specifics:** Linear SSM (continuous-time LTI: x'=Ax+Bu, y=Cx) used as the temporal aggregator; variants S4, S4D, and S5. S5 uses a DIAGONAL state matrix A∈R^(P×P) with block-diagonal HiPPO-N (LegS-Normal) initialization — hyperparameter J = number of HiPPO blocks, each block = A_LegSNormal; B̃=V^-1 B, C̃=CV via the diagonalizing eigenbasis. Discretization is the BILINEAR transform (not ZOH). Learnable per-channel timescale logΔ∈R^P initialized uniform over [log δmin, log δmax) with δmin=0.001, δmax=0.1. Frequency generalization: at inference the sampling rate r is rescaled (e.g. halved for 2× frequency) and Δ is rescaled directly — no retraining. One recurrent SSM per stage → 4 SSM layers total; state carried across event windows.

**Head & context injection:** Output/detection head = YOLOX on the multi-scale backbone features. Global context is injected inside each stage via Grid-SA (dilated attention giving a global receptive field) stacked after Block-SA (local windowed attention); the SSM layer then mixes temporal context across the whole feature map and carries persistent recurrent state between timesteps. There is NO per-point/per-event head — output is dense bounding boxes, not per-event labels.

**Complexity & latency:** Linear-time recurrence in sequence length (SSM scan). Trains ~33% faster than the RNN/ConvLSTM RVT baseline. Inference latency (batch 1, T4 GPU, Gen1): S5-ViT-S 7.81 ms, S5-ViT-B 8.16 ms, S4D-ViT-B 9.40 ms. Bandlimiting/masking adds negligible cost (zeroing C rows). Frequency change at test time is free (rescale r and Δ).

**Accuracy & datasets:** Gen1 (304×240, 39h): S5-ViT-B 47.7 mAP, S5-ViT-S 46.6, S4D-ViT-B 46.2 (vs GET-T ~47.9, ERGO-12 50.4). 1 Mpx (720×1280, ~15h, run at 640×360): S5-ViT-B 47.8, S4D-ViT-B 46.8, S5-ViT-S 46.5. DSEC used for cross-dataset generalization. Headline result: trained at 20 Hz then tested at other frequencies, SSM models drop only 3.76 mAP on average vs 21.25 (RVT) and 24.53 (GET) — frequency robustness is the paper's main contribution. Event representation: 50 ms windows (20 Hz) split into T=10 temporal bins, rasterized to a dense grid like RVT.

**Pitfalls / limits:** (1) Deploying above the training frequency causes ALIASING — the continuous-time SSM's high-frequency state modes fold back; mitigated but not eliminated. Two fixes: (A) output-C masking — compute each mode's effective frequency f_n=(Δt/r)·|Im(a_n)|/(2π) and zero C_n when f_n>α/2 with α=0.5 (empirically tuned for diagonal A); (B) an H2-norm regularizer suppressing response beyond ω_min (slightly better at very high freq). (2) α is empirically set, not principled. (3) Does not beat the best non-SSM detectors at the training frequency (e.g. ERGO-12). (4) It is DENSE detection: no per-event output, no graph, no serialization order — input is already rasterized into voxel bins, so the SSM only recurs over the ~10-bin/window sequence, not over the raw event stream.

**Design takeaways:** - LEARNABLE PER-CHANNEL TIMESCALE Δ IS THE KEY LEVER. Parameterizing logΔ∈R^P (init uniform in [log δmin,log δmax], e.g. 1e-3..1e-1) and rescaling it with the true event rate lets one trained model run at arbitrary inference frequencies with only ~3.76 mAP drop vs >20 for RNN/attention. For a per-event segmenter with variable event density this is directly transferable: tie Δ (or the discretization step) to actual inter-event Δt so the state decays in physical time, not in event-index steps.
- USE A DIAGONAL/S5-STYLE SSM WITH HiPPO-N (block-diagonal, J blocks) + BILINEAR DISCRETIZATION. It gives linear-time recurrence, cheap state carry across windows (7-9 ms/step here), and 33% faster training than a ConvLSTM — a good backbone for streaming per-event state that must persist across micro-windows.
- EXPLICITLY BANDLIMIT THE STATE TO KILL ALIASING WHEN INPUT RATE > TRAINING RATE. Their trick: compute each mode's effective frequency f_n=(Δt/r)|Im(a_n)|/2π and mask output C_n when f_n>α/2 (α≈0.5), or add an H2-norm penalty. A per-event model that will see bursty/high-rate windows should similarly cap the state's temporal bandwidth rather than trusting learned decay alone.
- SEPARATE LOCAL, GLOBAL, AND TEMPORAL MIXING INTO DISTINCT SUB-LAYERS. Their block = local windowed attention (Block-SA) → dilated global attention (Grid-SA) → temporal SSM. For a per-event segmenter, mirror this: local neighborhood aggregation (kNN/radius graph or submanifold conv) for geometry, a cheap global/context token or dilated pooling for the 'hand exists' prior, and a recurrent SSM purely for cross-window temporal state — don't overload one operator with all three.
- BEWARE: THIS PAPER IS NOT PER-EVENT. The SSM recurs over only ~10 rasterized voxel bins per 50 ms window, so it gives no guidance on serialization order, edge radius/kNN, or a per-event head — those remain open. To build a true per-event SSM segmenter you must add the missing piece: a stream ordering (time-sorted, or space-filling-curve serialization) and a per-event output head that reads the SSM state at each event's (x,y,t), which this architecture does not provide.
- RECURRENT STATE-CARRY ACROSS WINDOWS IS FREE AND EFFECTIVE. They persist one SSM state per stage between timesteps instead of re-encoding history — cheaper than BPTT-heavy RNN tracking and stable enough for streaming. For your event_segmentation path this argues for a lightweight persistent bottleneck state (the existing recurrent-GRU option) tuned in PHYSICAL time via Δ, rather than deeper temporal stacks.

## Part IV — Research findings by angle

8 angles were searched in parallel (each a `general-purpose` agent at high effort). Each angle's framing note (returned by the agent) is preserved, followed by its findings.

### Angle 1

*State-space models applied natively to raw, temporally-ordered event-camera streams for per-event / per-timestep prediction with linear-time recurrence. The field splits into three tiers: (1) TRUE event-by-event SSMs that ingest the raw (x,y,t,p) stream with an associative-scan linear recurrence and no spatial convolutions (Event-SSM, S7, STREAM) — the closest architectural match to a per-event segmentation backbone; (2) per-timestep streaming SSMs for regression/tracking (MambaPupil, adaptive-inference eye tracking); (3) window/voxel-tokenized Mamba backbones for detection/segmentation (SMamba, MambaSeg, PRE-Mamba) that keep linear complexity but abandon true per-event async processing. Crucially, ALL of these are classification/detection/regression — no published SSM does dense per-event semantic SEGMENTATION, so a per-event hand-seg SSM head is an open gap. Event-SSM's event-pooling downsampling and STREAM's coordinate-difference-driven Δ discretization are the two most directly reusable mechanisms for your row-aligned per-event logit head.*

- **Scalable Event-by-event Processing of Neuromorphic Sensory Signals With Deep State-Space Models (Event-SSM)** (2024 · arXiv preprint (Schöne, Sushma, Zhuge, Mayr, Subramoney, Kappel); code at github.com/Efficient-Scalable-Machine-Learning/event-ssm)
  - *Technique:* Deep S5-based linear SSM that ingests the RAW asynchronous event stream one event at a time — no frames, no spatial convolutions. Uses stable diagonal SSM parameterization, parallel associative scan along the event/sequence dimension for training, and a novel event-centric temporal downsampling ('event pooling') to shorten million-length streams. Integrates irregular inter-event time gaps directly into the discretization. Runs recurrently event-by-event at inference (async, energy-efficient).
  - *Key numbers:* DVS128-Gesture 97.7% (Event-SSM); Spiking Speech Commands 88.4% (+7.7 over prior SOTA); Spiking Heidelberg Digits high-90s; handles MILLIONS of events per sample (vs prior methods' ~thousands of timesteps); ~1.68 GFLOPs per DVS-Gesture sequence; ~small param budget (0.2M SSM core in the STREAM follow-up). Official code released.
  - *Relevance:* HIGHEST — this is the canonical native per-event SSM backbone and the exact template for a streaming per-event head. Its event-pooling downsampling is the analog of your spconv spatial-only downsampling, and its per-event recurrence is a drop-in alternative to your EventSparseSeg/EventSSMSegStream Koopman core. Only limitation: it outputs a single classification per sequence, so you must add a per-event readout (row-aligned logit per event) — the recurrence already carries per-event state so this is a lightweight change. Same lab also authored STREAM.
  - https://arxiv.org/abs/2404.18508
- **S7: Selective and Simplified State Space Layers for Sequence Modeling** (2024 · arXiv / ICLR-track (Zubić et al., UZH RPG))
  - *Technique:* Adds input-dependent SELECTIVITY (Mamba/S6-style content-dependent state transitions) on top of a SIMPLIFIED, stably-reparameterized S5-style diagonal SSM. Stable reparameterization controls gradient norm for very long sequences. Operates directly on raw event streams event-by-event like Event-SSM but with selective gating; keeps linear-time recurrence + parallel scan.
  - *Key numbers:* DVS-Gesture 99.2% (beats Event-SSM 97.7% and best dense BET 98.8%); Spiking Heidelberg Digits 96.3%; Spiking Speech Commands 88.2%; up to ~1.5M events per DVS-Gesture sequence; DVS128 128x128x2 channels.
  - *Relevance:* HIGH — the current SOTA for raw-event SSMs and a direct upgrade path over Event-SSM's LTI core. Input-dependent selectivity is exactly the mechanism that could let a per-event head gate hand vs background-noise events (your static-FP problem), while the stable reparam addresses the exploding/vanishing issues you'd hit on million-event hand-seg streams. Same classification-only output caveat — needs a per-event readout.
  - https://arxiv.org/abs/2410.03464
- **STREAM: A Universal State-Space Model for Sparse Geometric Data** (2024 · arXiv preprint (Schöne, Bhisikar, Bania, Nazeer, Mayr, Subramoney, Kappel))
  - *Technique:* Encodes spatial/temporal COORDINATE DIFFERENCES directly into the SSM discretization step: Δ_k = (t_k − t_{k-1})·softplus(δ), giving an O(N) linear recurrence h_k = exp(A_k Δ_k)h_{k-1} + B_k u_k processed per-point/per-event in sequential order with no neighborhood/graph construction. CUDA parallel scan for training. Unifies point clouds and event streams under one SSM.
  - *Key numbers:* DVS128-Gesture 100% (first to hit 100% on all 11 classes); STREAM core 0.2M params (+1.0M input encoder, ~1.2M total); ModelNet40 92.7% / ScanObjectNN-hardest 85.32% (12.3M); Spiking Speech Commands 86.3% (0.2M).
  - *Relevance:* HIGH — the coordinate-difference-driven Δ is the single most reusable idea for a per-event event-seg backbone: it lets the recurrence natively respect irregular event timing and 2D pixel geometry without voxelization, aligning with your per-event (coords, times) contract. Explicitly per-event and streaming. Caveat: paper reports classification only; a segmentation decoder/per-event readout is not provided and would be your novel contribution.
  - https://arxiv.org/html/2411.12603
- **MambaPupil: Bidirectional Selective Recurrent Model for Event-based Eye Tracking** (2024 · CVPRW 2024 (AIS workshop challenge winner))
  - *Technique:* Conv encoder over lightweight event representations + bidirectional GRU + Linear Time-Varying SSM (LTV-SSM) that selectively captures forward/backward temporal correlations. Emits PER-TIMESTEP pupil-position regression (streaming output, not a single label).
  - *Key numbers:* 1st place CVPR 2024 AIS Event-based Eye Tracking Challenge; combines EfficientNet-B3-style encoder + biGRU + LTV-SSM.
  - *Relevance:* MEDIUM — demonstrates an SSM producing dense per-timestep outputs on event streams (closer to segmentation's dense-output requirement than pure classification), and the LTV-SSM selective temporal gating is a useful pattern. But it uses a conv encoder over event frames rather than true per-event async ingestion, so it is streaming-per-timestep, not per-event.
  - https://arxiv.org/abs/2404.12083
- **PRE-Mamba: A 4D State Space Model for Ultra-High-Frequency Event Camera Deraining** (2025 · arXiv 2025)
  - *Technique:* Represents events as a 4D event cloud with dual temporal scales; a Multi-Scale State Space Model captures dynamics at LINEAR complexity. Critically formulates deraining as an EVENT-BY-EVENT CLASSIFICATION task (rain vs signal), i.e. a per-event binary label output — the same output shape as per-event segmentation.
  - *Key numbers:* Linear complexity over ultra-high-frequency streams; 4D event-cloud, dual temporal scales (see paper for EPM/precision numbers).

### Angle 2

*How Mamba/SSM methods serialize irregular point/event data into a 1D scan order, whether the scan is causal or bidirectional, how per-point segmentation heads are built, and the complexity — directly transferable to ordering (x,y,t) event points for per-event segmentation.*

- **PointMamba: A Simple State Space Model for Point Cloud Analysis** (2024 · NeurIPS)
  - *Technique:* Serializes FPS-sampled key points into a 1D sequence with Hilbert + Trans-Hilbert space-filling curves (locality-preserving: adjacent-in-sequence == geometrically close). KNN patches + PointNet token embed. Scan is CAUSAL/unidirectional; the two curve orders are concatenated and told apart by a learned per-curve 'order indicator' (scale gamma, shift beta) — this is the cheap substitute for a true bidirectional scan.
  - *Key numbers:* 12.3M params (vs Point-MAE 22.1M). ScanObjectNN 94.32% OBJ-BG, ModelNet40 93.6%, ShapeNetPart 86.2% ins-mIoU. Linear complexity; at seq len 32768: 30.2x faster, 24.9x less GPU mem, 5.2x fewer FLOPs than Point-MAE.
  - *Relevance:* Canonical recipe for turning unordered (x,y) points into a Mamba scan order. The Hilbert/Trans-Hilbert dual-order + order-indicator trick maps directly onto ordering event (x,y,t) points, and shows a causal SSM can work if you inject multiple complementary orderings.
  - https://arxiv.org/html/2402.10739v5
- **EventMamba: Rethinking Efficient Point-based Networks for Event Camera Classification and Regression** (2024 · arXiv (IEEE TIP line))
  - *Technique:* Directly treats an event stream as a pseudo point cloud (x,y,t,p) normalized to [0,1], with events STRICTLY CHRONOLOGICALLY ORDERED (t is the scan order — no space-filling curve needed because time is a natural 1D order). Hierarchical PointNet-style: FPS+KNN LocalFE -> attention-based Temporal AGgregation over K temporal neighbors -> Mamba GlobalFE. Unidirectional (causal) temporal scan.
  - *Key numbers:* Eye-tracking: 0.903M params, 476M FLOPs, 94.4% p3-acc / 1.48px MSE (beats PEPNet 91.8%/1.57px). DVS128 Gesture: 0.29M params, 0.219 GFLOPs, 99.6%. CPR: 5.5ms inference, 20% faster than PEPNet, ~8% better. Point sampling 0.065ms vs 0.457ms for frame stacking.
  - *Relevance:* Most direct precedent for this repo: same (x,y,t) event-as-point-cloud framing. Key design decision — order the scan by time rather than by a spatial curve — is the central choice for serializing event points, and it keeps microsecond temporal structure the SSM can exploit.
  - https://arxiv.org/html/2405.06116v2
- **Serialized Point Mamba: A Serialized Point Cloud Mamba Segmentation Model** (2024 · arXiv)
  - *Technique:* Per-point semantic/instance SEGMENTATION with a U-Net encoder-decoder (5 encode stages: pooling -> conditional positional encoding -> LN -> SSM -> LN -> MLP). Serializes via Z-order + Hilbert + their Trans- variants. TRUE BIDIRECTIONAL scan via a gated two-branch block: one branch forward, one reverses the sequence then does 1D-conv+SSM then un-reverses, combined by element-wise gating. Notes that at large channel width, using multiple serialization orders alone approximates bidirectionality.
  - *Key numbers:* 50M params base / 16M tiny. ScanNet v2 76.8 mIoU semantic, 40.0 mAP instance. S3DIS 70.3 mIoU. Lowest latency among baselines (5.6ms training latency on ScanNet v2). Linear complexity in sequence length.
  - *Relevance:* Shows the full recipe for a per-point (not per-object) segmentation head on serialized points — the closest analog to per-event dense labeling. Documents the explicit forward+reverse gated bidirectional scan and when multi-order can replace it, both relevant to whether the event scan should be causal (online) or bidirectional.
  - https://arxiv.org/html/2407.12319v1
- **Point Transformer V3 (PTv3)** (2024 · CVPR)
  - *Technique:* Foundational serialization framework: encodes each point's position into an integer along a space-filling curve (Z-order/Morton AND Hilbert), sorts all raw points into a 1D sequence, groups into fixed-size patches. Uses FOUR serialization patterns and shifts/alternates among them across layers so different curves expose different neighborhoods (a multi-order alternative to bidirectional scanning). Replaces KNN neighbor search with serialized neighbor mapping.
  - *Key numbers:* Attention/serialization is O(n) with patch grouping vs O(n^2); scales to full LiDAR scenes. SOTA on 20+ indoor/outdoor 3D seg benchmarks (transformer, not SSM — provides the serialization primitive).
  - *Relevance:* The reference definition of point serialization that PointMamba/Serialized-Point-Mamba build on. The 'shift across 4 curve patterns per layer' idea is a concrete recipe for giving a causal SSM multi-directional spatial context without paying for a reverse scan — applicable to alternating (x,y,t) scan orders across the sparse U-Net stages.
  - https://arxiv.org/html/2312.10035v2
- **Mamba3D: Enhancing Local Features for 3D Point Cloud Analysis via State Space Model** (2024 · ACM MM)
  - *Technique:* Argues vanilla Mamba's enforced causality + single direction is WRONG for unordered points. Adds Local Norm Pooling (LNP) for explicit local geometry, and a Bidirectional-SSM (bi-SSM): a token-axis forward SSM plus a novel BACKWARD SSM that operates on the FEATURE CHANNEL (not just reversed token order).
  - *Key numbers:* ScanObjectNN 92.6% OA, ModelNet40 95.1% OA, linear complexity. Bidirectional modeling reported to add ~5 points segmentation accuracy in smaller-param models.
  - *Relevance:* Direct evidence + ablation that bidirectional scanning materially helps unordered point data (the event cloud has no inherent spatial order along x/y). The channel-axis backward-SSM is an unusual bidirectionality variant worth considering alongside plain sequence-reversal.
  - https://arxiv.org/html/2404.14966v2
- **PRE-Mamba: A 4D State Space Model for Ultra-High-Frequent Event Camera Deraining** (2025 · arXiv)
  - *Technique:* Point-based event framework on a 4D event cloud that keeps native microsecond resolution: point = [x, y, (t-t0)/(te-t0)] with dual temporal scales. Spatio-Temporal Decoupling & Fusion (STDF) + Multi-Scale State Space Model (MS3M) capturing dynamics across dual-temporal and multi-spatial scales, linear complexity. Processes raw events directly, no voxel/frame quantization.
  - *Key numbers:* Linear complexity; SOTA event deraining; dual-temporal-scale 4D representation preserves microsecond precision.
  - *Relevance:* Second event-native SSM datapoint showing (x,y,t)-as-point-cloud + multi-scale SSM at full temporal resolution — supports keeping the event axis and scanning at multiple temporal scales rather than collapsing time (mirrors this repo's 'preserve the time axis' invariant).
  - https://arxiv.org/abs/2505.05307

### Angle 3

*Event-based GNNs treat each event as a node in a spatiotemporal graph over normalized (x,y,t), then exploit the directed/causal structure of the event stream to update only the local subgraph affected by each new event, giving asynchronous per-event inference at microsecond-to-millisecond latency. The line of work runs from AEGNN (the async-update foundation) through DAGr/EAGR (scaling depth for detection) to hardware (EvGNN FPGA) and motion-aware graphs (SMVL). This directly informs the repo's EventGraphSeg design (directed causal graph + max-relative op + micro-window streaming + presence gate): the field confirms per-event classification on FPGA is real, but dense per-event segmentation at ~1ms remains an unpublished gap, and the practical rate forces micro-window streaming rather than true one-event-at-a-time updates.*

- **AEGNN: Asynchronous Event-based Graph Neural Networks** (2022 · CVPR)
  - *Technique:* Builds an evolving spatiotemporal graph: each event is a node at normalized (x,y,t) (time scaled by a spatial-equivalent factor so radius search is isotropic); edges connect nodes within a fixed radius (radius-neighborhood graph), with node subsampling to cap graph size. Message passing uses SplineConv (continuous B-spline kernels on relative (dx,dy,dt) edge attributes). Trained synchronously, then converted at test time to an asynchronous network whose update rule recomputes activations only at nodes whose receptive field is touched by the new event.
  - *Key numbers:* Up to 11x fewer FLOPs vs SOTA async methods; 8x lower latency vs standard (dense) GNNs; ~20.1M params (as cited by later work); recognition on N-Caltech101 / N-Cars, detection on Gen1. CVPR 2022 (Schaefer, Gehrig, Scaramuzza).
  - *Relevance:* Foundational async-update GNN for events and the direct ancestor/baseline for the repo's EventGraphSeg. Establishes the radius-graph + normalized (x,y,t) + local-subgraph-recompute pattern the repo mirrors, and is the accuracy/FLOPs baseline every later paper reports against.
  - https://arxiv.org/abs/2203.17149
- **Pushing the Limits of Asynchronous Graph-based Object Detection with Event Cameras (EAGR / DAGr-style)** (2022 · arXiv (Gehrig & Scaramuzza; line continues into Nature 2024 'Low-latency automotive vision with event cameras'))
  - *Technique:* Introduces architecture choices (efficient async graph convolutions, lookahead/directed-graph design) that let the network scale to roughly 2x the depth of AEGNN while keeping per-event computation local and sparse. Processes events as a spatiotemporally evolving graph with async local updates per new event; adds a detection head on top of the deeper backbone. Breaks the shallow-network 'glass ceiling' that constrained prior async GNNs.
  - *Key numbers:* Smallest model: 3.7x lower computation than prior async methods with +7.4 mAP; larger model: 13% more efficient than SOTA with +11.5 mAP; 8.4 ms per forward pass and 3.7x faster than a dense GNN. Evaluated on Gen1 / 1Mpx (Gehrig & Scaramuzza).
  - *Relevance:* Shows async event GNNs can be scaled deep enough for competitive object detection, not just classification — the strongest evidence that the graph paradigm is viable for the repo's detection/segmentation ambitions, and the second key baseline (DAGr) that newer motion-graph work compares to.
  - https://arxiv.org/abs/2211.12324
- **EvGNN: An Event-driven Graph Neural Network Accelerator for Edge Vision** (2024 · IEEE (TU Delft); arXiv)
  - *Technique:* FPGA accelerator built around three ideas: (i) directed dynamic graphs where edges only point from past nodes to the new node (causal, edge-free storage — no explicit edge list needed); (ii) per-pixel event queues (grid of W×H queues, 16 entries deep) with a spatiotemporally DECOUPLED prism search range — spatial L1 constraint |dx|+|dy|<=rs and separate temporal dt<=rt — so no high-precision distance arithmetic; (iii) layer-parallel processing (all GNN layers run concurrently for a new event because causality fixes dependencies, cutting latency to the slowest single layer). Operator is a simplified PointNetConv: x_i = max_j Theta^T (x_j, |dx|, |dy|). Per-event node classification, updated incrementally.
  - *Key numbers:* N-CARS: 87.8% accuracy (INT8); 16 us per-event latency on Xilinx KV260, 9.2x faster than RTX A6000 software; 1.76 MB on-chip memory; 26.4% LUT / 18.3% DSP util. Projected 28nm ASIC: 10.7 us/event, 305 nJ/event, 2.5 mm^2. Max 16 neighbors/event.
  - *Relevance:* The concrete proof point that per-event GNN CLASSIFICATION runs at microsecond latency / sub-microjoule energy on real hardware — cited in the repo's memory as the '1ms reality check.' Its directed-causal, edge-free, max-relative (PointNet-style) design is essentially the hardware validation of EventGraphSeg's chosen operators; note it does classification, not the dense per-event segmentation the repo targets (the unpublished gap).
  - https://arxiv.org/abs/2404.19489
- **Event-based Graph Representation with Spatial and Motion Vectors for Asynchronous Object Detection (SMVL)** (2025 · arXiv)
  - *Technique:* Spatiotemporal MULTIgraph with two neighbor types: spatial neighbors within an ellipsoidal XY vicinity (edge features = normalized dx,dy,dt) and temporal neighbors over long time / small space capturing motion (edge features = velocity dx/dt, dy/dt and polarity change). SMVL block = Spatial Structural Learning (anisotropic 2D spline kernels k×k×1 over XY, ~87.5% cheaper than 3D kernels) + Motion Vector Learning (GATv2 multi-head attention over temporal neighbors), fused by concat+MLP. Per-event point-wise detection head (no fixed grid); nearby events pooled into 'active regions' for NMS. Fully asynchronous.
  - *Key numbers:* Vs AEGNN: +21% mAP on Gen1, 75% fewer params (5.6M vs 20.1M), 5x speedup, 4.5 MFLOPs/event (vs 5.26). Vs DAGr: +6% at similar cost. Datasets: Gen1 (39h automotive) + eTraM (10h surveillance).
  - *Relevance:* Current SOTA-direction for async graph detection and the clearest lever for the repo's motion/finger problems: it factorizes spatial structure from a per-event MOTION signal (velocity edges + attention) rather than a plane-fit feature — directly relevant to the repo's finding that per-event motion features must be discriminative to suppress FPs.
  - https://arxiv.org/html/2507.15150v1
- **EV-VGCNN: A Voxel Graph CNN for Event-based Object Classification** (2021 · arXiv)
  - *Technique:* Instead of one node per event, aggregates events into VOXEL-wise vertices (voxel graph) to exploit sparsity and shrink the graph, then runs a lightweight end-to-end graph CNN for classification. Reduces node count vs point-wise AEGNN-style graphs. Related NVS-S uses a slide-graph-convolution: only nodes/edges inside the K-hop subgraph of the new event (found via a sliding window) are updated.
  - *Key numbers:* Lightweight/low-power classification on N-Caltech101 (8,246 streams, 101 classes) and N-Cars; emphasizes voxel-vertex reduction vs point-wise graphs.
  - *Relevance:* Alternative graph-granularity choice bridging sparse-voxel (the repo's spconv path) and pure per-event graphs — a low-power classification design point showing voxel-node aggregation as a way to cut graph size, and NVS-S's sliding-window K-hop update is the same micro-window streaming idea the repo adopts because true one-event updates are too slow at dense event rates.
  - https://arxiv.org/abs/2106.00216v1

  Top URLs: <https://arxiv.org/abs/2203.17149>, <https://arxiv.org/abs/2211.12324>, <https://arxiv.org/abs/2404.19489>, <https://arxiv.org/html/2507.15150v1>

### Angle 4

*Two families of methods apply to per-event (x,y,t) hand segmentation on your sparse path. (a) Event-native graph/point-conv operators build a spatiotemporal graph over raw events and do message passing that respects sparsity and asynchrony — directly relevant as alternatives/complements to your spconv submanifold U-Net (EventSparseSeg). Key operators: SplineConv (AEGNN), slide/local-shift convolution for event-by-event incremental updates (SlideGCN), voxel-graph MFRL (EV-VGCNN/VMV-GCN), and graph-mixer/transformer message passing (GMNN/GTNN) which is the only published event-GRAPH *segmentation* line. (b) Point-cloud semantic-seg methods treat events as a 3D point set and give per-point label heads — KPConv/KPConvX (radius-kernel point convolution), PointNet++ (hierarchical set abstraction), RandLA-Net (random-sampling + local feature aggregation, cheap per-point head for large N), and Point Transformer V3 (serialization + windowed attention, avoids kNN — attractive because your event counts N are large). For your row-aligned per-event logit contract, RandLA-Net's attentive-pooling head and PTv3's serialized attention are the most drop-in efficient per-point heads; KPConv-style radius convolution is the closest point-conv analog to submanifold sparse conv. Caveat: nearly all event-graph work is classification/detection; dense per-event *segmentation* via graphs is essentially unpublished (GMNN motion/panoptic seg is the exception), so the point-cloud seg heads are the more mature source of per-point supervision machinery.*

- **Graph-based Asynchronous Event Processing for Rapid Object Recognition (SlideGCN / Local-Shift GCN)** (2021 · ICCV 2021 / AAAI (Local-Shift GCN))
  - *Technique:* Builds a spatiotemporal event graph and introduces 'slide convolution': instead of reprocessing the whole graph per event, it tracks added/deleted/updated nodes and propagates only feature deltas across GCN layers, plus a pixel-queue radius search (O(1) insert/delete) replacing k-d trees.
  - *Key numbers:* 11.5 vs 1152 MFLOPS/event (~100x less than naive sliding GCN); 16.9ms/event CPU vs 130.4ms; 76.1% N-Caltech101, 68.0% CIFAR10-DVS; early recognition ~12ms.
  - *Relevance:* Directly a per-event, event-by-event graph operator — the incremental-update trick is the graph analog of keeping the time axis alive in your sparse U-Net and could give true streaming inference for hand seg without reprocessing the whole window.
  - https://ar5iv.labs.arxiv.org/html/2308.14419
- **AEGNN: Asynchronous Event-based Graph Neural Networks** (2022 · CVPR 2022)
  - *Technique:* Events become graph nodes connected by spatiotemporal radius neighbors; message passing uses SplineConv (continuous B-spline kernels over relative node position, cost independent of kernel size). Trained densely but runs as sparse asynchronous per-event updates at inference, recomputing only affected receptive fields.
  - *Key numbers:* Up to ~200x fewer FLOPs vs dense CNN at inference; competitive recognition (N-Caltech101/N-Cars) and detection (Gen1) accuracy.
  - *Relevance:* Canonical event-graph operator and the reference for SplineConv on events; the async sparse-update inference model is what a low-latency hand-seg deployment would want. SplineConv is a candidate message-passing op if you move off spconv.
  - https://arxiv.org/abs/2203.17149
- **EV-VGCNN / VMV-GCN: Voxel Graph CNN for Event Classification** (2021-2022 · arXiv 2106.00216 / IEEE RA-L 2022)
  - *Technique:* Voxel-wise graph vertices (not point-wise) to cut node count; a Multi-scale Feature Relational Layer (MFRL) aggregates semantic+motion cues per vertex, and VMV-GCN adds a Volumetric Multi-View Fusion (VMVF) module over voxelized views.
  - *Key numbers:* EV-VGCNN 0.84M params, SOTA-for-complexity event classification; VMV-GCN low-complexity SOTA on classification + action recognition.
  - *Relevance:* Voxel-graph hybrid sits between your voxelized spconv backbone and pure point graphs; the MFRL/multi-view fusion is a cheap way to inject motion cues per vertex — echoes your motion-feature line — at very low parameter budget.
  - https://arxiv.org/abs/2106.00216
- **Asynchronous Events-based Panoptic Segmentation using Graph Mixer Neural Network (GMNN / GTNN)** (2023 · CVPRW 2023 (Event Vision))
  - *Technique:* Represents events as a 3D (x,y,t) graph and applies an MLP-Mixer / graph-transformer self-attention message-passing block for motion/panoptic segmentation, processing events asynchronously rather than as dense frames.
  - *Key numbers:* Reports competitive motion/panoptic segmentation IoU on event motion-seg benchmarks (EV-IMO-style); per-event asynchronous.
  - *Relevance:* The rare published example of event-GRAPH *segmentation* (not just classification) — the closest prior art to doing per-event hand/arm seg on a graph, and evidence that graph-transformer message passing works for dense event labeling.
  - https://arxiv.org/pdf/2305.03640
- **Finding Meaning in Points: Weakly Supervised Semantic Segmentation for Event Cameras** (2024 · ECCV 2024)
  - *Technique:* Forward+backward recurrent encoders over forward/backward voxel-grid views feeding shallow U-Net decoders; trained from sparse '1-Class-1-Click' point annotations (1 or 10 clicks per class) rather than dense masks.
  - *Key numbers:* DSEC-Semantic 45.55% mIoU (1C1C) / 51.19% (1C10C); DDD17 56.88/60.39; new DSEC Night-Point 36.4%.
  - *Relevance:* Point-click weak supervision is directly transferable to your SAM2-distillation setup as a cheap label source; the forward/backward recurrent-voxel design parallels your recurrent tracker and time-surface work.

- **EV-SegNet: Semantic Segmentation for Event-based Cameras** (2018-2019 · CVPRW 2019)
  - *Technique:* First dense event semantic-seg baseline: encodes events into a fixed multi-channel 2D representation (histograms + mean/std of timestamps per polarity) and runs a standard Xception/encoder-decoder CNN; releases the DDD17-seg dataset.
  - *Key numbers:* ~89% pixel accuracy / ~54% mIoU on DDD17-derived semantic set (6 classes).
  - *Relevance:* The reference baseline and evaluation protocol for event semantic seg; useful as a dense-frame comparison point and for its event-encoding channels (timestamp mean/std) that resemble your feats channels.
  - https://arxiv.org/abs/1811.12039
- **KPConvX: Modernizing Kernel Point Convolution with Kernel Attention** (2024 · CVPR 2024)
  - *Technique:* Point-cloud convolution via a set of continuous kernel points in a radius neighborhood; KPConvX makes it depthwise (nearest-kernel-point Hadamard product) and adds MLP-generated geometric-attention modulations from the center point's features.
  - *Key numbers:* S3DIS Area5 73.5% mIoU (+3.9 over KPConv, 35% faster, 50% memory); ScanNetv2 76.3% mIoU with 13.5M params.
  - *Relevance:* KPConv-style radius kernel convolution is the closest point-conv analog to your submanifold sparse conv, and gives a per-point seg head with strong accuracy; the depthwise+attention modernization is a low-FLOP swap for the spconv blocks operating on (x,y,t) points.
  - https://arxiv.org/html/2405.13194v1
- **Point Transformer V3: Simpler, Faster, Stronger** (2024 · CVPR 2024)
  - *Technique:* Serializes points via Z-order/Hilbert space-filling curves into ordered sequences, then does patch-windowed self-attention (Shuffle-Order across layers) with sparse-conv positional encoding (xCPE) — deliberately avoids kNN/radius search.
  - *Key numbers:* 3.3x faster, 10.2x less memory than PTv2; receptive field 16->1024 pts; ScanNet 77.9%, SemanticKITTI 74.2%, nuScenes 82.7% mIoU.
  - *Relevance:* Because event windows have very large N, PTv3's kNN-free serialized attention is an efficient per-point seg backbone/head that scales; the space-filling-curve serialization is a natural fit for (x,y,t) ordering and directly emits per-point labels.

- **RandLA-Net: Efficient Semantic Segmentation of Large-Scale Point Clouds** (2020 · CVPR 2020 (Oral) / TPAMI 2021)
  - *Technique:* Random point sampling (O(1)) instead of FPS, with a Local Feature Aggregation module = local spatial encoding (relative-position MLP) + attentive pooling + dilated residual blocks to preserve geometry despite random sampling; direct per-point MLP label head.
  - *Key numbers:* Processes 1M points/pass, up to 200x faster than prior; SOTA on Semantic3D and SemanticKITTI.
  - *Relevance:* The most efficient per-point semantic-seg head for very large N — a strong template for your row-aligned per-event logit output when event counts blow up; attentive pooling over local (x,y,t) neighbors is a cheap message-passing alternative to spconv.
  - https://arxiv.org/abs/1911.11236
- **Event-based Asynchronous Sparse Convolutional Networks** (2020 · ECCV 2020)
  - *Technique:* Reformulates a standard dense CNN into an equivalent sparse network that updates only the sites changed by each new event (recursive sparse convolution), preserving frame-trained weights while running asynchronously per-event.
  - *Key numbers:* Reports large FLOP reductions vs dense equivalent at inference with matched accuracy on recognition/detection.

### Angle 5

*Quantitative cost/latency/energy comparison of inference paradigms for event-camera vision — dense voxel-conv baseline vs asynchronous sparse-conv, event GNNs (incl. hardware accelerators), deep SSMs, and SNNs — plus the incremental/streaming tricks that make them cheap. The recurring headline: dense CNNs on voxel grids re-process the whole grid every window and are the FLOP/energy ceiling; sparsity + incremental (per-event recompute-only-affected-nodes) updates and linear-time recurrence are what buy 1-2 orders of magnitude. - **Event-based Asynchronous Sparse Convolutional Networks (AsyNet)** (2020 · ECCV)
  - *Technique:* Asynchronous submanifold sparse convolution: a network trained densely is run event-by-event, incrementally updating only kernel maps and feature vectors at sites touched by each new event (Rulebook-style delta propagation), so cost scales with the number of changed sites, not the grid.
  - *Key numbers:* Reported as a large fraction reduction in computation vs equivalent dense CNN; +2.0% accuracy over dense on N-Caltech101; CPU async implementation. Note: incremental-update bookkeeping overhead can offset gains when many sites change per event.
  - *Relevance:* Foundational proof that a submanifold sparse-conv net (exactly this repo's EventSparseSeg backbone family) can be executed asynchronously at a fraction of dense cost with identical or better accuracy — the canonical 'sparse-conv vs dense-conv' cost argument.

- **AEGNN: Asynchronous Event-based Graph Neural Networks** (2022 · CVPR)
  - *Technique:* Events as an evolving spatio-temporal graph; each new event adds a node and the update rule recomputes activations ONLY for graph nodes affected by that event (sparse recompute), avoiding full re-inference.
  - *Key numbers:* ~0.6 MFLOPs/event; 11x fewer FLOPs and 8x lower latency vs a standard (non-incremental) GNN; up to ~200x lower computational complexity vs dense-CNN pipelines; N-Cars accuracy ~86.7%.

### Angle 7

*Design guidance for a per-event (per-point) sparse hand-segmentation head with three coupled needs: (1) inject long-range/global context into an otherwise local per-event classifier, (2) positionally encode continuous (x,y,t) event coordinates, and (3) train a per-event binary head under severe foreground/background imbalance and noisy (SAM2-distilled, boundary/time-smeared) labels. The literature maps cleanly onto the existing EventSparseSeg + EventDistillationLoss stack: global context is best supplied by a learnable global token / attention-pooling read-out (Set Transformer PMA/ISAB, global-token point transformers) that broadcasts a scene summary back onto every event and can double as a presence/objectness gate; continuous (x,y,t) is best encoded with random or learnable Fourier features rather than raw coords (fixes MLP spectral bias); and the imbalance+noise regime is exactly what GCE/SCE/GJS, Asymmetric Loss, and the Lovasz hinge were built for — all already partly present in the codebase, with ASL and PMA-style global read-out as the main un-exploited levers.*

- **Set Transformer: attention-based permutation-invariant set functions (ISAB + PMA)** (2019 · ICML)
  - *Technique:* Pooling-by-Multihead-Attention (PMA): learnable seed/query vectors attend over all elements to produce a global summary; Induced Set Attention Block (ISAB) uses m inducing points to cut self-attention from O(n^2) to O(m*n).
  - *Key numbers:* ISAB reduces attention cost O(n^2) -> O(m*n) with m inducing points; PMA aggregates with k learnable seeds.
  - *Relevance:* Directly the mechanism for injecting global context into a per-event classifier: run PMA over all events in a window to get one (or k) global tokens, then broadcast/concatenate that token onto every per-event feature before the MLP head. This replaces the codebase's coarse /8 nearest-cell dense context (measured non-discriminative) with a learned, resolution-independent global read-out; the k=1 seed token can also serve as the per-window presence logit. Permutation-invariant, so it respects the unordered event set.
  - https://arxiv.org/pdf/1810.00825
- **Global transformer / global feature tokens for point-cloud context** (2024 · arXiv (Efficient Point Transformer w/ Dynamic Token Aggregating))
  - *Technique:* A small set of learnable global tokens exchanges information with all local point/voxel tokens (cross-attention), giving each point a linear-cost path to scene-level context instead of quadratic all-pairs attention; combined local+global transformer branches (LGFT-style).
  - *Key numbers:* Sparsified/aggregated tokens perceive global-context semantics; attention reduced from quadratic to near-linear via token aggregation.
  - *Relevance:* Confirms the Set-Transformer pattern generalizes to segmentation heads: global tokens raise the effective receptive field and suppress locally-ambiguous predictions (e.g. static-window false positives) by conditioning on a whole-scene 'is a hand present / where' summary — the exact failure mode logged for the GC model. Linear complexity matters for high event counts.
  - https://arxiv.org/html/2405.15827v1
- **Attention/multi-head pooling for per-point classification heads** (2024 · arXiv (Global Attention-Guided Dual-Domain Point Cloud))
  - *Technique:* Replace non-parametric max-pool global vector with multi-head attention pooling; the segmentation head concatenates the global feature with each point's local feature before the per-point MLP classifier.
  - *Key numbers:* Attention pooling scores/weights features vs. non-parametric max-pool that caps information transmission.
  - *Relevance:* Validates the concrete head design 'global-vector concat local-feature -> per-point MLP' that EventSparseSeg already uses, and shows attention pooling beats max-pool (max-pool 'loses significant information'). A drop-in upgrade path for the global-context injection without changing the per-event output contract.
  - https://arxiv.org/html/2407.08994v1
- **Fourier Features Let Networks Learn High-Frequency Functions in Low-Dimensional Domains** (2020 · NeurIPS)
  - *Technique:* Map raw coordinates v to [cos(2*pi*B*v), sin(2*pi*B*v)] with random Gaussian frequency matrix B (scale sigma tunable); NTK analysis shows this turns the MLP kernel stationary with tunable bandwidth, curing spectral bias so an MLP can fit high-frequency detail from (x,y[,t]) inputs.
  - *Key numbers:* gamma(v)=[cos(2piBv),sin(2piBv)], B ~ N(0, sigma^2); Gaussian mapping best; sigma (bandwidth) is the key hyperparameter.
  - *Relevance:* The canonical answer to 'how to positionally encode continuous (x,y,t) events': feed events' continuous coords through a random Fourier feature (RFF) mapping before the head instead of raw or bin-quantized coords. Fixes the sharp-edge / fine-finger high-frequency detail that raw-coordinate MLPs blur — matching the codebase's fuzzy-edge-under-fast-motion failure. sigma is the single knob trading detail vs. noise.
  - https://arxiv.org/abs/2006.10739
- **Learnable Fourier Features for Multi-Dimensional Spatial Positional Encoding** (2021 · NeurIPS)
  - *Technique:* Positional encoding via a learned linear projection of the multi-dim position into Fourier-basis (sin/cos) features, then an MLP; frequencies are trained end-to-end rather than fixed. Handles arbitrary continuous multi-dimensional coordinates and their cross-dimension interactions in one shared encoder.
  - *Key numbers:* Learnable frequency matrix + MLP over sin/cos of a linear projection of the D-dim position; reported gains over fixed/sinusoidal multi-dim PE.
  - *Relevance:* Best-fit PE for (x,y,t) jointly: unlike per-axis fixed sinusoids, one learnable Fourier projection encodes the 3D continuous event position and can learn anisotropic scaling of space vs. time (critical since t is in ms and x,y in px). Learnable frequencies adapt bandwidth to the data instead of hand-tuning sigma, and improve over fixed sinusoidal PE on spatial tasks.

- **AEGNN: Asynchronous Event-based Graph Neural Networks** (2022 · CVPR)
  - *Technique:* Treat events as an evolving spatio-temporal graph; per-event GNN with local neighborhood message passing over continuous (x,y,t) with normalized-coordinate edge attributes, convertible to asynchronous per-event updates at test time.
  - *Key numbers:* Up to ~200x FLOP reduction and ~8x latency reduction vs. dense/standard-GNN baselines at similar accuracy.
  - *Relevance:* Domain-matched precedent for per-event dense processing over continuous (x,y,t): shows coordinate-normalized edge features are the standard PE surrogate in the event-native setting, and that local message passing alone lacks scene context (motivating the global-token add-on above). Useful reference for combining a local per-event backbone with a global read-out.
  - https://arxiv.org/abs/2203.17149
- **Objectness / presence gating and background rejection for open-set segmentation** (2022 · arXiv (CF-RPN: classification-free object proposals))
  - *Technique:* A classification-free objectness score (from location/shape cues) or a preemptive background-rejector gate that routes low-objectness queries to a 'background' outcome before/independent of class prediction; open-set methods learn to reject rather than force-classify.
  - *Key numbers:* Objectness estimated purely from location/shape to avoid overfitting to seen categories; explicit background/unknown leaf.
  - *Relevance:* Formalizes the presence-gate the codebase already prototyped: a per-window objectness/'hand present?' logit that log-sigmoid-gates every event logit is exactly the background-rejector pattern, and pairs naturally with the global token (the token computes objectness). - **Generalized Cross Entropy (GCE) + Symmetric Cross Entropy (SCE) for noisy labels** (2018 · NeurIPS 2018 (GCE) / ICCV 2019 (SCE))
  - *Technique:* GCE = (1 - p^q)/q interpolates CE (q->0) and noise-robust MAE (q=1); SCE = CE + a*reverse-CE (MAE-like) adds a symmetric noise-tolerant term. Both bound the loss contribution of mislabeled samples (symmetric losses provably noise-robust).
  - *Key numbers:* GCE L=(1-p_y^q)/q, q in (0,1]; q->0 = CE, q=1 = MAE; SCE = alpha*CE + beta*RCE.
  - *Relevance:* Directly the theory behind the codebase's existing sce/gce/gjs terms; confirms these are the right family for SAM2-distilled labels that are wrong at boundaries and window edges. GCE's q and SCE's reverse-CE cap gradient from the smeared/ignored-band events, complementing the boundary_ignore/time_ignore masking. GJS (Jensen-Shannon) is the consistency-regularized generalization already in EventDistillationLoss.
  - https://pmc.ncbi.nlm.nih.gov/articles/PMC11747755/
- **Asymmetric Loss (ASL) for extreme positive/negative imbalance** (2021 · ICCV)
  - *Technique:* Decouples focal focusing for positives vs. negatives (gamma+ small/0, gamma- large) and adds asymmetric probability shifting: shift negative probability by margin m and hard-clip, discarding easy/mislabeled negatives while keeping full positive gradient.
  - *Key numbers:* Typical gamma+ = 0, gamma- = 2-4, probability margin m ~ 0.05; SOTA on MS-COCO/VOC/NUS-WIDE/OpenImages.
  - *Relevance:* The strongest un-exploited lever for this stack: per-event hand segmentation is exactly 'few positives, overwhelming negatives' plus label noise — ASL's two mechanisms (asymmetric focusing + probability-shift/hard-threshold) both down-weight the flood of easy background events AND drop likely-mislabeled boundary events in one loss, addressing imbalance and noise jointly. Drop-in per-event replacement/addition to the current BCE/focal terms.
  - https://openaccess.thecvf.com/content/ICCV2021/papers/Ridnik_Asymmetric_Loss_for_Multi-Label_Classification_ICCV_2021_paper.pdf
- **Lovasz-Softmax / Lovasz-hinge: differentiable IoU surrogate for imbalanced segmentation** (2018 · CVPR)
  - *Technique:* Lovasz extension of the (submodular) Jaccard set-loss gives a convex, differentiable surrogate that directly optimizes IoU; sorts errors by margin and weights under-segmented/misclassified elements most, aligning the loss with the set-level IoU metric rather than per-element CE.
  - *Key numbers:* Optimizes Jaccard/IoU directly via Lovasz extension; consistently improves mIoU over CE, especially on imbalanced/small classes.
  - *Relevance:* Confirms the set-level Lovasz-hinge already in EventDistillationLoss is the right choice for the sparse foreground: it directly optimizes the IoU/F1 that val reports and naturally emphasizes small/under-segmented hand regions ignored by pointwise BCE — the complement to per-event ASL/GCE. Best used on top of a pointwise robust term, not alone.
  - https://arxiv.org/pdf/1705.08790

### Angle 8

*As of 2024-2025, the event-vision backbone field has split into two camps: (1) synchronous accuracy leaders — Recurrent Vision Transformers and their SSM successors (S5/Mamba) that voxelize events into dense tensors and win on mAP/mIoU, and (2) asynchronous efficiency leaders — GNNs and the new spatially-sparse linear-attention detectors that process events event-by-event at microsecond latency but trail on absolute accuracy. SSMs (S4/S5/Mamba) are now the dominant "best of both" backbone: linear-time temporal scaling, train-at-one-rate/deploy-at-another via the continuous-time hidden state, and adaptive token sparsification (SMamba) that claws back GNN-like efficiency without abandoning GPU-friendly dense kernels. True SSM+GNN hybrids essentially do not yet exist as named published models — the closest analogs are (a) GNNs that internally adopt a two-timescale "fast local update + slow contextual aggregation" design that mirrors an SSM's recurrent state (DAGr/HUGNet/EAGR), and (b) linear-attention detectors (SSLA-Det) whose per-location "mixture-of-spaces" sub-states are a graph-structured SSM in disguise. This is the open white space directly relevant to the repo's own EventSSMSegStream (SSM) vs EventGraphSeg (GNN) fork: the literature validates each separately but has not fused them, so a state-space model whose recurrence runs over a sparse event GRAPH is a genuinely underexplored, publishable direction. Note the repo already sits near this frontier — its Koopman/S5 per-event stream (val F1 0.786) and CMRConv graph model are independent reinventions of the SSM and GNN camps respectively.*

- **State Space Models for Event Cameras** (2024 · CVPR 2024 (Spotlight), Zubic et al., UZH-RPG)
  - *Technique:* S4/S5-style SSM layers with a lightweight ViT backbone; learnable timescale so you train at one event rate and deploy at another without retraining (continuous-time discretization).
  - *Key numbers:* ~33% faster training than RNN-based recurrent transformers; smaller accuracy loss under frequency shift; CVPR 2024 Spotlight.
  - *Relevance:* The foundational paper that made SSMs the default modern event backbone and the direct ancestor of the repo's EventSSMSegStream/Koopman line. Establishes the train-rate/deploy-rate decoupling argument the repo relies on.
  - https://arxiv.org/abs/2402.15584
- **SMamba: Sparse Mamba for Event-based Object Detection** (2025 · AAAI 2025)
  - *Technique:* Mamba (selective SSM) with adaptive token sparsification: spatio-temporal continuity assessment discards noise tokens, information-prioritized local scan shortens scan distance between high-info tokens, plus 3D global channel interaction.
  - *Key numbers:* 22-31% FLOP reduction vs dense baseline; best accuracy+efficiency on Gen1, 1Mpx, eTraM; AAAI 2025.
  - *Relevance:* Current SSM SOTA for event detection and the strongest evidence that SSMs can absorb GNN-style sparsity while staying on dense GPU kernels — most relevant reference point for arguing an SSM backbone over a graph backbone.
  - https://arxiv.org/abs/2501.11971
- **MambaSeg: Harnessing Mamba for Image-Event Semantic Segmentation** (2025 · AAAI 2026)
  - *Technique:* Dual-branch parallel Mamba encoders for RGB + event streams with a Dual-Dimensional Interaction Module (cross-spatial + cross-temporal fusion).
  - *Key numbers:* DDD17 mIoU 77.56% (+2.53 over EISNet), acc 96.33%; DSEC mIoU 75.10% (+2.03), acc 95.71%; AAAI 2026.
  - *Relevance:* Directly on the repo's task (event segmentation) and shows Mamba beating the prior transformer/fusion SOTA (EISNet) at lower compute — the segmentation-specific analog to SMamba.
  - https://arxiv.org/abs/2512.24243
- **SSLA-Det: Low-latency Event Detection with Spatially-Sparse Linear Attention** (2025 · arXiv 2026 (preprint))
  - *Technique:* Linear-attention with state-level sparsity via a 'mixture-of-spaces' decomposition — events activate only location-specific sub-states (a graph-structured recurrent state), scatter-compute-gather for GPU parallel training, YOLOX head with event-by-event async updates.
  - *Key numbers:* Gen1 0.375 mAP with >20x fewer FLOPs than prior best; beats DAGr-L (0.321) with 171x fewer FLOPs; N-Caltech101 0.515 mAP / AP50 0.743; per-event 0.10-0.72 MFLOP; <10 us CPU latency. Claims first end-to-end async linear-attention event detector.
  - *Relevance:* The closest thing to an SSM/GNN hybrid: per-location sub-states are effectively a state-space model laid over a spatial graph. Bridges the accuracy-vs-async gap and is the single most relevant paper for the repo's SSM-vs-GNN fork.
  - https://arxiv.org/abs/2603.06228
- **eGSMV: Event Graph Representation with Spatial and Motion Vectors** (2025 · arXiv 2025)
  - *Technique:* Decoupled multigraph GNN — a spatial graph with anisotropic 2D B-spline kernels plus a temporal graph with motion-vector attention; fully asynchronous event-by-event inference.
  - *Key numbers:* Gen1 mAP 0.371 (vs AEGNN 0.163, DAGr 0.212-0.304); eTraM mAP50 0.431 (+25% vs AEGNN); 4.5 MFLOP/event vs RVT ~3520; 5.6M params (vs AEGNN 20.1M); 5x speedup.
  - *Relevance:* Current GNN SOTA and the strongest counterargument to going pure-SSM: it nearly doubles AEGNN accuracy at ~780x less per-event compute than RVT. Defines the GNN camp the repo's EventGraphSeg belongs to.
  - https://arxiv.org/abs/2507.15150
- **GET: Group Event Transformer** (2023 · ICCV 2023)
  - *Technique:* Transformer backbone using 'Group Token' representation that groups events by timestamp+polarity, decoupling temporal-polarity from spatial info via Event Dual Self-Attention + Group Token Aggregation.
  - *Key numbers:* Outperforms prior SOTA on Cifar10-DVS, N-MNIST, N-CARS, DVS128Gesture + Gen1/1Mpx detection; ICCV 2023.
  - *Relevance:* Reference transformer backbone that motivates SSM/linear-attention successors (its dense attention is the cost SSMs undercut). Frequently the baseline SSM and GNN papers compare against; also relevant to the repo's two-channel polarity handling.
  - https://arxiv.org/abs/2310.02642
- **Event cameras in 2025 (Gregor Lenz survey blog, Part 2)** (2025 · Blog survey)
  - *Technique:* Survey/opinion comparing SSM vs GNN vs Transformer vs SNN backbones; argues for a two-stage 'lightweight streaming tokenizer -> stateful temporal (SSM) model' design.
  - *Key numbers:* HUGNet v2: ~1000x latency cut at similar accuracy; EvGNN hardware: ~10x energy efficiency vs GPU; SSM optical flow ~4.5x faster / ~8x fewer MACs than iterative TMA; SNNs flagged as slow-to-train/underperforming.
  - *Relevance:* The single best synthesis of the SSM-vs-GNN-vs-SNN tradeoff landscape and explicitly notes NO named SSM+GNN hybrids exist yet — confirming the white space. Names DAGr/HUGNet v2/EvGNN (GNN), SMamba/PRE-Mamba (SSM), RVT (transformer).
  - https://lenzgregor.com/posts/event-cameras-2025-part2/
- **Hybrid SNN-ANN / Hybrid Spiking Vision Transformer for Event Detection** (2025 · ICML 2025 / CVPR 2025)
  - *Technique:* Hybrid Spiking Neural Network + ANN (or Spiking ViT) backbones with a bridge module converting sparse spatial-temporal spikes into dense feature maps for a detection head.
  - *Key numbers:* CVPR 2025 (Hybrid SNN-ANN, spatial+temporal attention) and ICML 2025 (Hybrid Spiking ViT); positioned as efficiency-focused, accuracy below SSM/transformer SOTA.
  - *Relevance:* Represents the SNN camp and the SNN-hybrid trend; useful as the low-power/async contrast point to SSM and GNN, and confirms pure SNNs still lag on accuracy (motivating hybridization).
  - https://arxiv.org/html/2505.07715v1
- **PRE-Mamba: 4D State Space Model for Event Deraining** (2025 · ICCV 2025)
  - *Technique:* Multi-scale 4D (spatio-temporal) SSM for ultra-high-frequency event streams.
  - *Key numbers:* ICCV 2025; efficient long temporal context, small param count (task = deraining, not detection/seg).
  - *Relevance:* Evidence that SSMs scale to dense high-rate 4D event volumes with small parameter footprints — supports the linear-time temporal-context argument central to the repo's SSM direction.
  - https://arxiv.org/abs/2505.05307
